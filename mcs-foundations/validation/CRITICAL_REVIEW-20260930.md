## 七条批判与实际修正

| 批判 | 原来为什么不足 | 实际修正 |
| --- | --- | --- |
| DEF 与义务混标 | 契约通篇是「须 / 不得」的义务条款，却自称 DEF；定义不能自带义务 | 开头把「定义」与「接口义务（验收条款）」分成两类；两处义务标题由（DEF）改为「接口义务」；明说第 04 章定义坐标、后文兑现义务之前本附录不能独立核验 |
| 先修被相对化掏空 | 先修只对声明的路线族成立，新路线可推翻，却没说结论何时算稳定、呈现时要不要带限定 | D.3 规定只在声明族内报告、未经枚举完整性证明是可修订搜索结论；D.4 给出两条稳定性判据：声明范围 + 枚举完整性，并要求呈现与下游引用携带限定 |
| Adapt 签名未定死 | 「若需读取 M 就显式传入 M」让核心函数签名悬空 | 定规范签名 `Adapt(E,s,g,b)`（不含 `M`）；需读 `M` 的适配器改用 `Adapt_M(M,E,s,g,b)`，两种签名分开命名、分开检查，不增加局部化算子 |
| 学习者无关近乎同义反复 | 只要求「替换输入不改版本」，挡不住内容错误，防御力弱 | 改写为「卫生约定，非泄漏检测结论」：只规范 M 变更路径可审计，明说挡不住误登记、最终须由实现核验更新入口 |
| 可检查名不副实 | 机读清单不验证自然语言论证，但「可检查」的口径没写死 | D.6 定义「可检查 = 断言—证据可追溯 + 机读清单可核对 + 核验可复现」，明确不等于机器证明 |
| 高阶类型动机只是承诺 | D.2 只有「要量化关系」的断言，没有具体断言 | 给出子关系许可传递的例子（若 r⊆s，凡 r 许可的步骤 s 也许可），并注明必要性由第 02、05–08 章兑现、此处不单独证明 |
| 否定句过多、无正向不变式 | 每段以「不 / 不能 / 不等于」收尾，读者拿不到正面保证 | D.6 末新增「正向保证（可依赖项）」：版本不变式、可审计、范围性、可复现、可追溯五条 |
