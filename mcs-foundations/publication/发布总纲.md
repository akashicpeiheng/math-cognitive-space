# MCS 专稿发布总纲

#MCS #研究出版 #规划

版本：2026-10-02 / 编辑方案 v0.1。本文的发布选择是编辑决策（DEF）；读者效果尚待试读（NOT-CLAIMED）。未收到更细的受众偏好时，采用“中文阅读为主入口、独立论文承担研究主张、复现材料提供核验”的工作假设。

## 1　新的定位

对外总题采用 **《数学认知空间 MCS：数学资源、证据与学习路线》**。副题采用“公共知识与个人学习状态分离的研究专稿”。“完整理论”保留为旧文件名与历史版本名称；新封面用具体对象说明范围，避免读者从“完整”推断研究或工程已经全部完成。

一段式介绍：

> 同一个数学对象，可以从不同问题进入，也可以用不同方式表达。MCS 研究如何记录这些资源之间的条件、证据与来源，并据此构造可检查的学习路线。它将公共数学资源、外部学习者状态和派生视图分开，使不同入口共享数学依据，同时保留各自的未知与限制。当前成果包括形式规范、附条件的数学论证和有限实现；实际教学收益仍是待检验的问题。

这个定位有两条动机。数学内部需要防止“提到了某概念”被当成“证明依赖它”，也需要防止“换了表达”丢掉条件。学习实践需要允许不同背景的人进入同一目标，并说明路线建议用了哪些假设。构造链因此是：**条目与连线 → 成组输入和替代行动 → 带证据与来源的资源 → 外置个人评价的事件路线 → 针对具体模型的独立检验**。这是设计动机，不是历史发生或心理发展规律的实证描述。

## 2　五种交付物，各自回答一个问题

| 交付物 | 核心读者与问题 | 形式及篇幅预算 | 发布成立的条件 |
| --- | --- | --- | --- |
| 问题导读 | 有数学学习经验的初读者：为什么需要这些区分？ | 中文独立文章；以一个案例贯穿，约 2–4 千字预算 | 能独立读完，有误区、边界、原文入口；至少一次外部试读 |
| 研究正文 | 希望理解整体设计的读者：资源如何成为路线？ | 中文可导航 Markdown；以后生成网页和 PDF；六部分 | 每部分给出问题、直觉、关键形式、例子、失败边界与回看题 |
| 形式基础与核验 | 数学审阅者、实现者：推理依赖什么？ | 独立技术册；保留原编号、来源与证据状态 | 每条主要保证能回溯假设、证明或明确的有限报告 |
| 独立论文 | 研究同行：一个问题上增加了什么可审查结果？ | 英文论文；先保持一篇，正文页数服从目标场合 | 核心问题集中，相关工作定位成立，主结果经独立审阅，包可复跑 |
| 复现材料 | 复核者：哪些结果能重现？ | 版本化代码、输入、报告、运行说明 | 在声明环境中重跑；来源及结果哈希匹配；明确可信边界 |

篇幅是编辑预算（DEF），不是已完成指标。交互站点是案例演示入口，单独报告软件版本与测试范围；它不承担论文证明，也不要求读者先配置服务才能读懂专稿。

## 3　重构阅读顺序

现有原章序适合沿形式依赖审查。公开主入口改成：

1. 从群的多个入口看见问题，再读新增导读。
2. 学会区分节点、出现概念、支持、共同条件。
3. 连接行动与来源，再引入个人状态。
4. 用视图和有界规划组织路线。
5. 在极限、流形、张量和群之间比较哪些结构相同、哪些桥梁不同。
6. 集中回答反例、证据与下一步研究。

形式基础在技术册按“接口 → 元理论 → 语言 → 语义 → 结构 → 核验”组织。主册使用技术册中的结论时仍须链接原条件，改变阅读顺序不改变逻辑依赖。两册各部分的具体映射见[内容编排](内容编排.md)。

本次已交付的是新导读、两册编排和导航。新章节开场、逐条件反例的全稿补齐、图示与语言统一列为下一阶段工作，不把重新拼接称为已经重写全稿。

## 4　首篇论文聚焦“路线中的资源义务怎样保持”

拟议题目：**Evidence-Preserving Routes over Versioned Mathematical Resources**。中文工作题为《带版本数学资源的路线与证据保持》。这是下一轮编辑目标，尚未替换现有英文稿题名、PDF、摘要或投稿包。

中心问题：当资源经过组合、视图隐藏与个人筛选时，哪些条件保证原有证据义务仍可追踪、可核对？

主结果层次如下。

| 在论文中的位置 | 保留的内容 | 当前依据与边界 |
| --- | --- | --- |
| 主线 | 带来源的事件路线与组合保持 | 原第 06、12 章及英文稿 `thm:preservation`；PROOF，相对于局部有效性等假设 |
| 算法保证 | 全部候选维度有限且判定可终止时的界内搜索 | 原第 12 章及英文稿 `thm:search`；PROOF；实现只覆盖列明片段 |
| 贯穿案例 | 极限的两种表述与资源证据层次 | 英文稿第 3 节；正文证明与局部机器证书分开 |
| 表示边界 | 保留同等信息的增强图编码 | 英文稿第 7、9 节；保留同等结果，不以删去对照信息制造优势 |
| 支持性失败例 | 无约束概念出现聚合的饱和 | 原第 05 章及英文稿 `thm:saturation`；作为动机或附录，是否留正文取决于主线需要 |
| 讨论 | 外部模型的识别与实证缺口 | 原第 16 章；不能从规范推得实际教学效果 |

建议论文顺序：失败案例与研究问题 → 相关工作及差异 → 最小资源接口 → 路线保持定理与假设反例 → 有界算法 → 等信息比较与复现 → 限制。高阶语义、36 个局部化方案、全部学科层级保留在技术册，不挤入首篇论文的中心叙事。

**关于新颖性。** 当前资料支持“接口整合、条件可审查、有限复现”这一贡献描述，尚不支持“首创知识网络”“表达能力普遍更强”或“提升学习效率”。是否足以形成独立研究论文仍需补充相关工作对照与同行判断。若最终只剩已有接口的重述，则改为研究技术报告，不为维持投稿计划而增加未经证明的口号。

**后续论文的启动条件。** 暂不按章节预定系列论文。完整案例认证形成可独立评估的实现与保证后，才考虑工具论文；真实模型比较或干预结果成立后，才考虑实证论文；支持族算法产生独立结果后，才考虑理论论文。每篇都须有新的中心问题和证据，避免把同一贡献拆成若干重复稿。

## 5　渠道按职责选择

| 渠道 | 在本方案中的职责 | 当前状态 / 启动条件 |
| --- | --- | --- |
| 本地 Obsidian / Markdown | 工作母版、试读和修订 | 已可阅读；保留一份编排清单 |
| 在线专稿页面 | 长期阅读与版本导航 | 规划中；先完成试读再选部署方式；不把当前本地站点说成公开专稿网站 |
| 可引用归档（候选 Zenodo） | 固定版本、引用信息与配套材料 | 未创建记录；在内容冻结、授权与文件清单确认后执行 |
| arXiv | 聚焦英文论文的预印本 | 现有稿仅本地准备；分类按最终主贡献评估，不沿用“标题含学习便选 cs.AI”的推断 |
| 期刊 / 会议 | 获得同行审阅 | 暂不指定刊名和截止日；P1 定稿后按范围、篇幅和当期政策筛选 |
| 专题文章渠道 | 帮读者进入一个问题 | 优先从导读改写；每篇指向一个稳定版本，不维护新的理论副本 |

平台事实与编辑选择分开。arXiv 的非英文提交需要完整英文版本，因此这里把中文专稿与独立英文论文分别组织；这不要求先把全部中文技术册翻成英文。参见 [arXiv 非英文稿件规则](https://info.arxiv.org/help/faq/multilang.html)。TeX 投稿需要准备相关源文件，并检查系统生成的 PDF，参见 [arXiv TeX 提交说明](https://info.arxiv.org/help/submit_tex.html)。

Zenodo 可以为更新的文件建立相连的新版本记录；这是其适合作为候选归档渠道的依据，不表示本项目已经获得 DOI。参见 [Zenodo 版本管理](https://help.zenodo.org/docs/deposit/manage-versions/)及 [DOI 说明](https://help.zenodo.org/docs/deposit/describe-records/reserve-doi/)。同一内容已有 DOI 时需按其规则处理，论文与补充材料也应正确区分。上述四页于 2026-10-02 核对所述规则；没有调查具体期刊政策、作者账户权限或接受概率。

## 6　沟通口径与读者反馈

公开短介绍以三件事收束：**研究什么、目前给出了什么、下一步怎样检验**。证据边界写在读者需要它的位置；将运行细节和全面责任表留给技术册，避免导读被维护信息淹没。

首批试读只检验可读性：请读者用自己的话解释 M/E/D，指出哪一步第一次不懂，分辨“呈现了定理”和“证明了定理”，找到一条结论的前提。记录原话、卡点和修订位置；这些反馈不作为教学效果实验。

六个候选专题依次为：同一份数学为何有多个入口；一条知识连线藏了哪些意思；提到一个概念是否意味着依赖它；把图缩小后怎样保住条件；可找到一条路线与已经学会的区别；给研究结论标证据的方法。每篇围绕一个问题，来源固定到同一专稿版本，发布频率服从材料成熟度。

## 7　思想、方法与回看

**思想：让不同文本承担不同阅读任务，让同一主张共享同一证据来源。** 方法是第 2 节的读者—交付物配对、第 4 节的单问题收束，以及第 5 节的渠道分工。

保留一条编辑试错：把完整框架压成一篇论文，容易让定义数量替代核心贡献；纠正手段是逐项问“删掉这部分，中心问题还能否成立”。这是一项编辑判断，需由试读和同行审阅继续检验。

回看问题：如果读者只记住一个结论，他能同时说出该结论的条件和证据吗？如果不能，先改叙事和主张，再增加发布渠道。
