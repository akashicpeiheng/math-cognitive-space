# MCS 笔记创作使用与迁移说明

创作台帮助作者回答“该写什么、为什么写、怎样检查”。正式入口为[人工写作指南](MCS节点写作指南.md)与[AI 写作提示词](MCS节点AI写作提示词.md)，版本 `mcs-learning-node-template / 2026-10-19.1`。

## 两类模板与私人创作

公共学习节点 L 使用阅读模板，形式对象 M 使用独立的[形式对象指南](MCS形式对象写作指南.md)与[AI 提示词](MCS形式对象AI写作提示词.md)，其模板标识为 `mcs-formal-object-template / 2026-10-19.1`。两者的模板 ID 都不是文档 ID，也不是 `mcs-node/1`、`mcs-object/1` 协议版本。

可复制文件集中在[模板目录](../../../mcs-content/templates/README.md)：普通学习节点、无对象引用的方法论节点，以及五级形式对象。占位符草稿不在正式扫描范围内；填写后须与依赖组成候选库，通过共享解析器检查才能进入正式内容。引用摘要由工具取得，不由 AI 猜测。

当前创作台仍保存私人笔记 E：继续使用 YAML 和章节标记，采用更新后的讲解规则，不自动添加公共 mcs-node 身份。个人经历、掌握状态与写作进度留在 E。定义、定理、证明等角色只组织呈现，不给节点赋数学尺度。

旧 mcs-object-note 是兼容标识。打开和保存旧稿保持标识、版本与正文；“复制为创作稿”也保留已识别的旧模板标识。只有主动选择“预览类型变更或模板升级”并采纳后才升级，原文与自定义章节保留。历史类型卡和校准样稿不自动更新，ima 模板不迁移。

本轮检查入口、结果及 Lean 基线状态见[模板分离验收](模板分离验收-20261019.md)。

## 开始与继续

1. 打开“我的笔记库”，点“新建笔记”，填写标题、主要角色、读者基础。附加角色可以多选；默认最小核心，可主动选择深度长文。未定或陌生角色会提示专用检查不足。
2. 从数学节点页点“围绕此节点写笔记”可预填标题和关联；关联可修改或移除，仅为私人参考。
3. 左栏可自由跳转章节，中间写当前节，右栏直接回答具体写作问题。无需先读完长指南。示例与起笔框架默认折叠，只有主动插入的框架会进入正文。
4. 使用“完整 Markdown”处理跨节内容、自定义章节和原稿；“阅读预览”检查公式、段落与已带入的附件，复制稿未首次保存时也可预览附件。分章节与全文共享同一正文。
5. 到“新建笔记”页的“继续本机草稿”，或已保存创作笔记旁的“继续创作”恢复。草稿属当前浏览器及站点来源，不跨设备自动同步。

网站路径为 `/library/write/new`、`/library/write/:draftId`；英文界面带 `/en` 前缀。切换网站语言不翻译正文。笔记的 `mcs-language` 决定新增框架和提示词语言。

## 最小核心与按需展开

默认先交代对象与任务、背景与约定、精确内容、依据与边界。定理、推论、证明、构造、算法、例子与反例等角色另选论证资源；证明可以准确引用，不必写第二条证法。角色可以组合，例如同一绝对值函数同时是连续的例子和连续必可导的反例。

左栏“按需展开资源”保留历史、直觉、应用、联动、总结等引导。选择资源后，点击“加入本节”或把适用性改为“适用”才加入正文。深度长文可选择全套资源，但不要求凑两条动机、六步直觉、迁移题、历史或个人试错。生长链允许分叉与竞争定义；价值不必是优于旧方法。

适用性独立于写作进度：

- 适用：检查本篇是否已有对应内容。
- 不适用：简述理由，正文允许无该标题。
- 本篇不展开：超出当前任务，可记录引用入口；不要求凑理由或正文。
- 尚未确定：保留具体问题，不计为完成，也不擅自填成不适用。

核心义务不可豁免。“本节内容由哪里承担”可选择同篇已有章节，避免重复：例如背景约定已写在精确内容中。不存在、重复或循环的承载关系会提示修正。原有正文不会因此自动删除；可在全文编辑中调整排版。

右栏可以补充“本对象独有的问题或检查”。陌生对象提示代表元／辅助选择依赖、等同层次及混合断言，不能据核心齐全推定所有义务已覆盖。条件分析允许冗余、依赖、表达失去意义或待查，不强迫每个条件产生反例。

## 暂存、版本与下载

输入进入 IndexedDB 暂存，事务完成后才显示“草稿已暂存在当前浏览器”。“保存笔记版本”将当时快照与草稿基线原子提交，生成私人笔记库修订。保存过程中继续输入的文字属于下一稿，编辑器保留它们。未完成内容始终可保存；库中可阅读历史版本。

“下载 Markdown”保全编辑器当前文字，包括尚未保存的修改。它是单篇 Obsidian Markdown，附件仍需从库备份保留。“导出笔记库”继续使用现有 JSONL 备份机制，包含所有修订和附件。自动暂存不代替独立备份；移除浏览器站点数据会同时移除草稿。

写作状态由作者选择：未开始、写作中、待核验、已自检；“不适用”另属适用性。内容、承载来源或数学背景改变会使相关自检失效；角色改变使已有自检退回写作中。界面分别显示核心和选中展开的文字覆盖，未知另提示，不判断证明正确、史料可信或学习效果。

## 旧稿、附件与账号工作副本

旧笔记或历史修订旁点“复制为创作稿”，生成独立新稿。来源写入 `mcs-source`，原库和 Obsidian 原文件保持原样。相对目录结构带入新路径，可唯一解析的直接附件随稿复制；笔记链接和不能解析的引用列成待处理清单，不暗中选择歧义目标。依赖其他笔记的传递嵌入不会自动扩展成整库复制。

旧稿可先全文编辑；“预览类型变更或模板升级”展示补充后的全文，只添加核心与本篇选中的缺失章节，保留自定义段落、公式、代码块与链接。原有稳定章节标识仍沿用。预览后继续写作时，采纳动作会先以最新正文更新预览，需要核对后再次采纳，不覆盖新修改。

账号笔记点“取回本机继续写”会下载该库完整文件清单和内容，核对哈希并保留账号修订基线。MCS 创作稿可直接继续；其他导入笔记仍复制成独立新稿。保存只改本机；主动“上传到我的账号”才提交新账号修订。账号切换取消未完成请求，上传映射按账号分隔，本机副本仍由使用者管理。

## 冲突与失败恢复

| 情况 | 结果与下一步 |
| --- | --- |
| 同一稿件被另一标签页暂存 | 停止覆盖，保留当前编辑器文字；可先下载，再重新读取暂存稿，或将当前文字另存一份 |
| 同一已保存笔记被其他操作修改 | 拒绝提交；比较最新库版本或另存，当前稿仍在 |
| 同库其他笔记增加版本 | 若目标文件哈希未变，可在最新库修订上保存；事务内再次核对库版本 |
| 可用空间不足或 IndexedDB 写入失败 | 不显示成功回执，版本提交回滚，文字留在编辑器；下载后释放空间，再另存或重新载入 |
| 上传中断 | 云端旧修订保持有效；再次主动上传恢复未完成批次 |
| 云端修订已在别处更新 | 拒绝静默覆盖；保留并导出本机稿，比较账号最新版本。可复制为新稿或另存当前文字 |
| 旧标签页阻挡存储升级 | 关闭旧 MCS 页面后重新载入；不删库重建 |
| 章节标识重复或标题改坏 | 章节模式提示无法安全定位；全文模式继续编辑、下载和保存，重复标识需手动修复 |

本轮不提供自动合并。上传成功后的本机笔记库仍可继续写，之后需再次主动保存和上传。

## 提示词与个人材料

三种按钮分别装配整篇、当前节、审校提示词；组合已选角色的义务，并读取适用性、理由和同篇承载关系；不补回省略的模块。章节辅助也携带完整原稿（含精确命题、背景及自定义引理），但只输出目标章节。审校分数学缺口、证据缺口、可选深化建议。额外材料保存在本机草稿，明确作为参考数据；它们不成为新的执行指令。剪贴板受限时，焦点置于提示词预览后可全选复制。

复制不调用模型，也不上传正文。AI 不得虚构历史、文献、用户试错经历或完成的验证；作者自行核查后采纳输出。“我当时以为……”仅能来自本人材料，不能让模型编成亲历。

## 数据与模板维护

- `shared/writing-template.mjs` 维护阅读章节、双语引导、角色差异与节点提示词；`shared/formal-template.mjs` 独立维护五级形式对象范本与提示词。两者共用纯 Markdown 格式生成器，正式准入继续使用 `shared/content-documents.mjs`；`TemplateDefinition`、`NoteDraft`、`WritingCheckResult` 为私人创作内部契约。
- `npm run templates:build` 生成四份指南/提示词、七份可复制 Markdown 范本及历史适配样稿。四份指南同步到网站与现有 Obsidian 模板目录；范本统一放在 `mcs-content/templates/`。原六篇 v1 和十一篇适配校准稿保留原模板版本，已有样稿内容不同时拒绝覆盖。`npm run templates:check` 检查一致性，`npm run test:writing` 验证正文、双文档范本与浏览器闭环。
- IndexedDB 由 1 升至 2，只新增 `writing-drafts`。原库、历史、文件分块、目录句柄和上传映射继续保留，不自动重导入。
- Markdown frontmatter 中保存 `mcs-template`、`mcs-template-version`、`mcs-type`、`mcs-language`、`mcs-audience`、`mcs-source`、`mcs-status-*`，并新增 `mcs-roles`（逗号分隔角色）、`mcs-depth`（core/deep）、`mcs-applicability-*`（applicable/na/deferred/unknown）、`mcs-reason-*`、`mcs-covered-*`（承载章节 ID）、`mcs-custom-checks`。更新只改 MCS 自有字段，其他 YAML 与正文保留。旧 `mcs-status-*: na` 兼容读为不适用，旧正文作为理由，不自动改写；旧标题仍可定位。无需新增 IndexedDB 版本。光标、预览状态与附加提示词材料不写入正文。
- 旧模板只增加新版入口说明，完整原始字节作为后缀保留。核验报告继续原处保留；[原文哈希记录](旧模板保留记录.json)可核对。ima 的生产模板、配置、流水线账本和归档策略均沿用原版本。

本轮未新增模型调用、公有本体发布、学习者掌握写入或 Obsidian 原文件写回接口。数学与历史审校记录见[样稿与来源核验记录](样稿与来源核验记录.md)。

适配案例与本轮验证边界见[适配验收记录](适配验收记录.md)。
