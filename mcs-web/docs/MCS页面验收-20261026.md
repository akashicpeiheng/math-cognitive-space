# MCS 多尺度页面验收记录（2026-10-26）

`/mcs` 与 `/en/mcs` 已接入主导航。页面读取当前 65 个正式数学对象和 92 条 M 层关系，提供五级尺度放缩、成员展开／合拢、组合滤镜、对象与区域拖动、本机恢复和 URL fragment 分享。浏览状态只保存在浏览器或分享链接中，不改公共 M/L，也不写学习者 E 记录。

本轮的工程验收结果是：构建、doctor、国际化检查、MCS 纯函数／API 测试和 MCS 真实浏览器测试全部通过；默认 `npm test` 因本机 Lean 累计预算超时而未完整变绿。其余非 Lean 阶段通过分段续跑全部通过。把仅用于测试的 Lean 预算延长到 300 秒后，两份真实 Lean 测试 20/20 通过；默认超时明确属于 `EVIDENCE_RESOURCE_EXHAUSTED / timeout`，不是命题被反驳或证明核对失败。

## 全量测试中的 Lean 边界

默认预算下出现四处同源超时：

- `tests/lean-live.test.mjs` 的登记重放与负例重放在 `target_audit` 报 `EVIDENCE_RESOURCE_EXHAUSTED`、`reason: timeout`；该组为 18/20 通过、2 项超时。
- `tests/auth.test.mjs` 的公网 Lean 任务轮询未在 120 秒内得到终态。
- `tests/https-public.mjs` 的浏览器 Lean 重放等待 130 秒超时。
- `tests/lean-page.mjs` 的浏览器终态等待 130 秒超时。

这些失败都发生在同一 Lean 资源预算上，没有产生数学失败报告。测试脚本支持用 `MCS_WEB_TEST_LEAN_TIMEOUT_MS` 为 Windows 验证环境单独延长隔离预算；不延长生产证明验收时限，也不改变 Lean 内核。

随后用 300000 ms 的隔离测试预算重跑 `tests/lean.test.mjs` 与 `tests/lean-live.test.mjs`，20/20 通过。登记重放耗时约 394.6 秒；负例、伪造报告和更强目标拒绝组耗时约 898.5 秒，总进程约 21 分 56 秒。负例覆盖直接 `sorry`、间接 `sorry`、自定义公理、原生公理、更强目标、缺声明，以及零退出但没有 audit report。这个结果只说明本机在更长预算下通过真实内核重放，不改变生产配置中的预算。

## 未验证与未声称

- 本轮真实浏览器验收使用 Chromium。Safari、Firefox 和实体触屏设备尚未实测；双指转单指使用同一 React 指针处理链上的活动指针夹具补充验证。
- 没有做真实学习者实验，因此 240／180 px 与 220 ms 只是工程初始值，不声称有认知科学依据或教学收益。
- 57 个拓扑—微分几何对象没有登记上层成员，页面只展示其内部声明；没有新增数学分类或聚合。
- 英文界面和页面文案已提供；对象正文仍是中文，并在英文界面显式标为未翻译。
- 分享链接保存的是公共视图状态，不包含账号、个人笔记、学习事件或登录凭据。
