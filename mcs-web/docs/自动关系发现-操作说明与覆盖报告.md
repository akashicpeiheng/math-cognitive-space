# 自动关系发现与验证：操作说明与覆盖报告（首版）

> 证据状态标注沿用 [`mcs-foundations/15-验证与完成标准.md`](../mcs-foundations/15-验证与完成标准.md)：
> `DEF / PROOF / REF / FINITE / ILLUSTRATION / NOT-CLAIMED`。
> **「已覆盖 / 未覆盖 / 未验证」三栏必须分开看**——把后两栏并成一个数字，
> 这张表就会把「本轮没写」和「写了但没验证」说成同一件事。
>
> 施工图与接口定义见 [`自动关系发现-接口与语言规格.md`](自动关系发现-接口与语言规格.md)。

## 1. 这份东西是什么

一条完整流程：**在网站填写新节点的形式表达 → 系统自动发现候选关系 → 验证其中一部分 →
展示依据 → 审阅后把节点与选定关系加入公共知识网络**。

首版**独立于 AI 服务**运行：本机规则搜索、本机证明生成、本机独立检查。
自然语言/LaTeX 自动翻译、开放式类比发现、教学效果预测、完整数学证明助手**都不在范围内**。

## 2. 怎么用（网站操作）

入口有两处：

1. **节点详情页** → 「以此为基础创建」/「检查已有形式表达」；
2. **网站维护** → 「自动关联」。

主流程固定为六步，界面不会跳过中间步骤：

| 步骤 | 你做什么 | 系统做什么 | 不做什么 |
|---|---|---|---|
| 1 填写节点 | 名称、类型、案例、简介、自然读法 | 草稿自动保存（本机，不依赖学习者档案） | 不替你补解释内容；缺的显示「待补充」 |
| 2 检查表达 | 选背景、声明参数类型、写公式 | 解析、类型检查、规范化、给出可读预览；错误定位到行列 | 不把解析失败当成"命题为假" |
| 3 自动发现 | 点「开始发现」 | 生成候选、装配证明、跑独立检查器、核对目标 | 不放宽预算；到点返回部分结果并列出未处理数 |
| 4 审阅结果 | 看分组、展开每条的根据 | 按**已验证 / 已反驳 / 未决**分组；给方向、条件、理由、证据范围、重放结果 | 已反驳与未决项**不画成已成立关系** |
| 5 入库预览 | 勾选要采纳的 | 给出完整变更清单（节点、关系、证据、契约） | 预览**零写入**，不改公共图 |
| 6 确认入库 | 确认 | 六步事务 + 原子切换生效版本 | 失败时原版本继续生效；重复提交返回同一结果 |

**回滚**在「自动关联 → 历史版本」里：回滚创建**新的一条版本记录**，
不删除历史包、证据或学习者记录，并保证当前公共网络没有悬空引用。

键盘可达、窄屏可用；结果状态同时用文字与视觉区分（不只靠颜色）。

### 3.2 未覆盖（本轮明确不做）

| 项 | 为什么不做 | 什么时候可以谈 |
|---|---|---|
| 自然语言 / LaTeX 自动翻译 | 需要外部模型，且与"本机独立运行"冲突 | 有可核验的翻译层之后 |
| 开放式类比发现 | 不是规则可判的；首版只做六类有明确定义的关系 | 另行立项 |
| 跨载体遗忘映射、一般理论解释、自动对偶发现 | 需要跨理论翻译，本轮没有可核验的判据 | 见规格文档 §4 |
| 完整 Cayley 定理 | 三段义务（双射 / 同态 / 像为子群）中只有单射片段有证书 | 逐段补证书，不合并成一句 |
| `smooth ⇒ C^k 图册` 那条泛化 | **差一条数学事实**（`smooth ⇒ is_ck(·)(k)`），它不是定义展开；按界线**故意没有** stipulate | 补上那条事实的证书 |
| `ε–δ 极限 ↔ 序列收敛` 的直接等价 | 需要去心邻域/聚点那一层展开，超出首版原子谓词 | 另登记一层展开 |
| 任意模型的自动搜索 | 首版只检查预置有限对象 | 需要模型搜索器 |
| 完整数学证明助手 | 内核只有 16 条规则的子集，没有一般高阶合一 | 见 `mcs-foundations` 的既有边界 |
| 教学效果 | 需要对照研究 | 在此之前不作任何声称 |

## 4. 验证记录

1. 原有四份证书**必须照样重放通过**（本轮不改 `kernel.py`，不改历史证书）；

### 4.2 四条既有证书的闭合

既有四份局部证书的结论含自由变量、且带开放假设，kernel 的 `theorem` 规则拒绝引用
开放假设非空的引理。`core/formal/lemmas.mjs` 的 `closeCertificate` 把它们闭合为：

| 证书 | 闭合后 | 步数 |
|---|---|---|
| `group.json` `cayley-evaluation-injective` | `∀g h. equal_left_translations(g,h) ⇒ B(g = h)` | 31 + 3 |
| `manifold.json` `chart-self-transition` | `∀y. right_inverse_at_y(y) ⇒ B(chart(inverse y) = y)` | 9 + 2 |
| `tensor.json` `rank-one-additivity` | `∀alpha v x y. alpha_additive(alpha) ⇒ B(…)` | 34 + 5 |
| `limit.json` `constant-sequence-value` | `∀a ∀n. B(lift(λx.a)[a](n) = a)` | 8 + 2 |

四份都 `kernel passed`、`open_hypotheses = {}`。闭合**只追加** `imp_i` / `all_i` 步骤，
原有步骤一字未改；`object_conclusion` 字段被去掉（留着会被判 `HOL/FOL translation mismatch`），
这一条写在 `closeCertificate` 的 `notes` 里，不是悄悄删的。

### 4.3 关系重放入口（长期）

```bash
npm run verify:relations          # 只核对已认证 / 曾压手的那些
node scripts/verify-relations.mjs --all   # 连未认证的也试一遍，便于看差在哪
```

它按登记的形状**重新生成目标、重新跑证明搜索、重新起 `kernel.py` 判定**，并据此报告
「通过 / 与登记不一致 / 本轮没走到」。这个脚本留在版本库里是有原因的：登记表里那些
`machine-certified` 字段是一句**承诺**，承诺必须能被当场核对，否则它只是文字。
（`tmp/team/*` 下的探针是排障用的一次性脚本，`tmp/` 被 gitignore，换台机器就没有了。）

本轮实测（2026-10-04）：

| 关系 | search | kernel | 步数 | 开放假设 |
|---|---|---|---|---|
| `rel:concept:abelian-refines-group` | proved | **passed** | 12 | 0 |
| `rel:concept:linear-refines-additive` | proved | **passed** | 8 | 0 |
| `rel:manifold:chart-atlas-generalizes-ck-atlas` | proved | **passed** | 10 | 0 |
| `rel:manifold:ck-atlas-generalizes-smooth-atlas` | 未认证，跳过 | — | — | — |

**这个脚本能证明什么、不能证明什么**（不夸大）：

- **能**：这条关系的目标，从登记里声明的那几条背景公理出发，**确实能搜到证明**，
  且装配出的证书被真检查器判 `passed`、开放假设为空。
- **不能**：它**没有逐字节复现**签出时那一份证书。登记里记的 `theorySha256` /
  `proofSha256` 与本次重算的不同——因为理论装配路径与搜索顺序都会影响结果
  （同一命题可以有多条合法证明）。所以这里核的是「目标可由声明的公理证明」，
  而**不是**「这份证书与当初那份一模一样」。这个区别写在脚本输出的 `·` 备注里，
  不藏起来。

### 4.4 界面核对（本机无头 Chrome）

`tests/authoring-page.mjs` 用真浏览器跑：六步流程都在页面上、草稿栏在、形式表达编辑器在、
**故意写坏的公式会被拦下并回报行列位置**、审阅与入库预览的容器在、
节点详情页两个入口在（「以此为基础创建」「检查已有形式表达」）、
窄屏（420×900）下六步重排而不隐藏、没有 `tabIndex<0` 的暗坑、控制台零 JS 报错。

本机**没有可用的 Electron 二进制**（内置浏览器 provider 自报不可用），所以交互式浏览由
无头 Chrome + Playwright 承担；两者是不同路径，这一点如实记在这里，不混为一谈。
