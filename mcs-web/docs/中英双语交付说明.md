## 三、四条不变量（改代码前先读）

1. **中英是同一份本体、同一个版本**。语言覆盖在 `createOntology()` 算出 `contentHash`
   **之后**才应用，所以 `zh` 与 `en` 的 `ontologyVersion` 逐字相同。这不是省事：档案与事件
   挂在 `ontologyVersion` 上，两个哈希等于两套互不可见的证据。→ `tests/i18n-core.test.mjs`
   直接断言两条相等，`npm run check` 的 `[8]` 节每次复核。
2. **只换文本，不换结构**。id、`discipline`、`construct`、`roles`、`mode`、证据标签、
   LaTeX 与公式一律不动。→ 两道门逐条核对。
3. **缺译文 = 回落中文 + 如实标注**。不会变成空白，也不会编一段英文。→ 英文站的未译条目带
   `i18n-pending` 标记与提示（**只加在看得见的位置**：`<option>` 这类看不见的控件不加装饰）。
4. **事件标识与时刻恒与语言无关；自由文本注解随操作时的界面语言**。`eventId`/`kind`/
   `occurredAt` 中英逐字相同（所以档案互通）；`payload.note` 这类**给人读的注解**按操作时的
   语言写（`LearnerActions`、`recordReview` 已如此；`SelfCheckTasks` 的学习者原文永不翻译）。

## 五、独立复核：英文侧横向抽查（只读，不改译文）

由一位**不参与正文翻译**的成员在 **4856 个「真的译过」的字段对**上跑四项扫描，另出一张
**21 格中英并排抽样表**（覆盖 6 个案例，选点全部落在**条件 / 反例 / 否定范围 / 边界**
这些最容易被抬高或说反的位置）。结论：**未发现数学错误**；发现并已修正：

| 项 | 结果 |
|---|---|
| 公式 `$` / `$$` 计数 | **0 / 4856 不一致** |
| 证据措辞被抬高 | **1 处真错**：`tensor:infinite-rank` 的英文多出 `is proved`（源文只说「实质使用」）→ 已改回 `is used` |
| 英文散文混进中文标点 | **1 处真错**：全角 `（` 配半角 `)` → 已改；另 17 处命中都在**允许照抄的中文文献反引号内** |
| 术语 / 记号 / 人名 | 术语未发现漂移；记号差异经查是**渲染面不同**（元数据用 unicode、正文用 LaTeX）；人名专名统一。另统一 3 处排版写法（`ε-δ`→`ε–δ`、`infinite-redshift surface`） |
| `\varnothing` : `\emptyset` 混用 | **不动**：中文源自身 19:8 混用，逐块照抄是正确的——**公式逐字规则优先于排版美观** |

**这份抽查的边界（必须与结论一起引用）**：它**不能证明**「英文侧已核对」。它只说明：在
术语、记号、人名、证据措辞这四个**可横向比较**的维度上，以及在这 21 格抽样里，没有发现
问题。它不覆盖数学正确性、语体与逐句忠实度；已译正文只抽了约 14%。机械扫描的已知盲区：
段落加粗只判有无不判个数；跨文件术语一致性依赖候选词表（词表外的同义改写抓不到）；
记号扫描只覆盖列出的那些写法。

## 六、工具查不到的、必须人看的（**这一节比判据全绿更重要**）

**以下四项本轮没有做，或只做了抽样**——如实列出来，是为了不让读者把「判据全绿」
读成「译文已核对」：

- **数学正确性（本轮未做，最重要的一项）**：两道门都不检查。把「不收敛」译成「收敛」、
  把条件方向译反，工具看不出来。独立复核做了 **21 格并排抽样**（约 14% 的已译正文，
  选点集中在条件 / 反例 / 否定范围 / 边界）**未发现问题**——但**抽样不能替代全量复核**，
  其余约 86% 仍待人工看。抽样方式见 `docs/i18n-施工手册.md` §5。
- **措辞是否被抬高**：`REF`/`not_run` 附近的英文有没有被写成 verified/certified——工具只比
  标签的**计数**，不比语气。独立复核逐条过了 199 条证据、命中 1 处并已修正
  （`tensor:infinite-rank` 的 `is proved` → `is used`）；这是一类**只能靠人看**的修正。
- **句内加粗的保真**：结构判据只问「这一段里有没有加粗」（查位置会被中英语序差异误报），
  所以 `公理里**没有**分离性` 这类**句内**加粗若被漏掉，工具不会响。
- **术语是否漂移**：同一中文概念在不同块的英文写法是否一致；`glossary.mjs`（654 条）是基准，
  但没有判据强制逐块对齐。独立复核做了候选词表比对 + 最容易出错的一对
  （过渡映射 vs 坐标变换）逐块并排核对，未发现漂移；**词表外的同义改写抓不到**。

## 七、剩余缺口（如实）

1. **形式内核的背景理论登记表**（`core/formal/backgrounds.mjs`，8030 汉字、5 个背景理论）：
   它经 `/formal/catalog` 下发给「自动关联」页与形式表达编辑器，**不在 `data/i18n/` 覆盖层的
   管辖内**（覆盖层当前只管 `data/`）。英文站的 `/en/authoring` 背景下拉因此仍是中文标题。
   正确修法是**扩展覆盖层**（`data/i18n/en/formal-backgrounds.mjs` + `/formal/catalog?locale=en`），
   **不是**给内核加英文字段——内核保持纯中文源。任务已登记（`task-21`）。
   同一处还有两个次来源（离线兜底 `FALLBACK_TEMPLATES`、界面文案 `FLOW_BOUNDARIES`），
   必须一起改，否则「目录不可用时英文站又变回中文」是很隐蔽的一类回归。
2. **中文源自身的排版缺陷**（工具单独列出并从相应判据豁免，不算译者的账）：
   - 5 处加粗标记不平衡（奇数个 `**`）：`dg:tensor`、`dg:tensor-product-dg`（2 处）、
     `dg:differential-form`、`liang:minkowski-spacetime`；
   - 1 处中文**裸写在数学模式里**：`dg:topological-space` 的 `$f^{-1}(开集)$`（导致该块的
     公式判据误报，已改为「源侧缺陷 + 两侧对称豁免」）；
   - `\varnothing` : `\emptyset` 源级混用 19:8；
   - `liang` 里 30 段引导词收尾 `**` 前多一个空格、53 段以半角句点收尾（`**动机. **`）。
   修它们要改中文源 → 会改 `contentHash`（= 本体版本号）→ 属**单独的站点内容变更**。
3. **`dg:smooth-atlas` 的公式在中文站上本来就是坏的**（既有源缺陷，非本轮引入）：
   源快照 `data/dg/dg-smooth-atlas.md` 把 `\mathbb` 写成 `\\mathbb`（356 处），而 KaTeX 里
   `\\` 是换行——中文块与英文块**逐字一致地继承**了这个写法。修它要改源快照并重新生成正文。

### 三条「给工具实现者」的经验（都属于同一族缺陷）

1. **按下标/位置对齐的比较，对「增删」零容忍**：剔除一个元素后仍按下标配对 → 后面**整体错位**，
   1 处差异被报成几十项（实测 1 → 60）。比较一律走**多重集差集**。
   同病另一态：**遮蔽/抠除必须等长**（`\text{闭 $p$-形式}` 里的 `$` 会打乱公式配对；
   长度一变，后面所有位置全错）。
2. **判断「是否含中文 / 是否需要豁免」必须看原文，不能看归一化后的值**：
   归一化恰好把待检特征抹掉 → 豁免条件**恒为假**、工具不报错、只是从不生效
   （看起来「检查通过了」，其实是没检查）。通用前置断言：**两侧剔除的条数必须相等**——
   它把「豁免静默失效」变成「当场报错」。
3. **同一约束写在两处 = 更容易误伤**：一处放宽了豁免、另一处没跟上，就长期挂一个假红
   （LaTeX 命令集曾在两支脚本里各数一遍）。**一个约束只在一个地方检查**，
   另一处只留哨兵（例如「检查脚本是否存在」）。

### 验收本身也会骗人：两类「假失败」

- **并发构建会清空 `web/dist`**（`build.emptyOutDir: true`），正在跑的浏览器验收拿到 404/白屏，
  表现成一串互不相关的断言失败（`.case-card` 为 0、页脚为空、最后 `browser has been closed`）。
  看起来像功能坏了，实际是产物被踩掉。修法：**冻结构建窗口**。
- **验收晚了一步**：某条动画窗口（wink 时的六缕丝绸）只存在约 100–300ms，
  而断言分两步做（先等它出现、命中后再读一次状态），机器繁忙时第二次读取时窗口已关。
  修法：**在轮询命中那一刻把状态取出来**（写进 `window.__x`），不要在窗外重读。
  共同点：**验收对时序做了它不该做的假设。**

   结构预演）收编进 `scripts/`——**口径已在施工手册 §6 固化**，实现直接搬即可。
