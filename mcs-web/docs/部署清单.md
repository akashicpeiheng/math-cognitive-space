# 部署清单：把 MCS Web 放到公网 https 上（第一版：只走 GitHub 登录）

这份清单按「**不发邮件**」这一版写：注册与找回密码如实回 503，登录走 GitHub OAuth。
邮箱发信接进来之后，把 `MCS_WEB_AUTH_EMAIL_ENABLED` 改成 `1` 并配好 Supabase 的 SMTP 即可，
其余步骤不变。

**托管平台有两条路，按你有哪张卡选**：

| | Render（第 2 节） | Hugging Face Spaces（第 6 节） |
|---|---|---|
| 需要境外信用卡 | **是**（Stripe 验证身份，$1 预授权不扣费） | 否 |
| 链接 | `https://<名字>.onrender.com` | `https://<用户名>-<space名>.hf.space` |
| 冷启动 | 闲置 15 分钟后休眠 | 闲置约 48 小时后休眠 |
| 配置方式 | 仓库根的 `render.yaml`（Blueprint 只问 6 个变量） | Space 设置里填 8 个 secret；代码推到 Space 仓库 |

---

## 0. 前置：仓库要能被托管平台读到

Render 从 Git 仓库部署，所以先要有仓库（GitHub）。

    # 在 E:\MCS（仓库根）执行；远程地址换成你自己的
    git remote add origin https://github.com/<你的账号>/MCS.git
    git add -A && git commit -m "MCS Web：账号、权限、PostgreSQL 与部署配置"
    git push -u origin master

> 推送前先确认导出审计是干净的（它会拦下密钥、用户目录路径与不该发布的材料）：
>
>     cd mcs-web && node scripts/export-open-source.mjs --out <一个空目录>

## 1. Supabase：认证 + PostgreSQL

### 1.1 建项目

1. 打开 <https://supabase.com> → New project（免费档即可，区域选离你近的）。
2. 等它初始化完成，记下两个值：
   - `Project URL`：形如 `https://abcdefgh.supabase.co`
   - `Publishable key`（anon key）：`Project Settings → API keys`

### 1.2 打开 GitHub 登录

1. **先建 GitHub OAuth App**：GitHub → Settings → Developer settings → OAuth Apps → New OAuth App
   - Homepage URL：`https://<你的站点域名>`
   - Authorization callback URL：`https://<你的 Supabase 项目>.supabase.co/auth/v1/callback`
   - 拿到 Client ID，生成一个 Client Secret。
2. **回到 Supabase**：`Authentication → Providers → GitHub` → 打开，填入上一步的 ID 与 Secret。
3. `Authentication → URL Configuration`：
   - Site URL：`https://<你的站点域名>`
   - Redirect URLs 加上 `https://<你的站点域名>/api/v2/auth/callback`
     （服务端的 OAuth 回调就走这个地址；少了它 GitHub 登录会停在 Supabase 的错误页）

### 1.3 邮箱确认

Supabase 默认「Confirm email」是开的。不发邮件时有两种选择：

- **推荐**：完全不用邮箱登录，把 `Authentication → Providers → Email` 关掉
  （站点上邮箱登录会失败并说明原因）；
- 或者保留 Email 但关掉 `Confirm email`（`Authentication → Sign In / Providers → Email`），
  这样注册不發信也能直接得到会话——**代价是任何人填任意邮箱都能注册**，
  等于放弃了邮箱真实性。

### 1.4 数据库连接串（**别用 Direct connection**）

在项目页点**右上角的 `Connect` 按钮**（不是 Project Settings），弹窗里选连接方式。三种模式：

| 模式 | 主机 / 端口长这样 | 能不能用 |
|---|---|---|
| **Session pooler** | `aws-0-<区域>.pooler.supabase.com:5432`，用户 `postgres.<项目ref>` | ✅ 首选 |
| **Transaction pooler** | 同上，端口 `6543` | ✅ 也能用（见下） |
| Direct connection | `db.<项目ref>.supabase.co:5432` | ❌ **在 Render 上连不通**（那个域名是 IPv6，Render 的出口连不上，启动时会报 `ENETUNREACH` / 连接超时） |

**找不到 Session pooler 时**：那个弹窗里通常有一个**下拉选择器**（默认停在 `Direct connection`），
点开就能看到 `Transaction pooler` / `Session pooler`。若确实只有 Transaction 一档，**直接用它**：

- 我们的代码不用命名预处理语句、不用 `LISTEN`/会话级 `SET`，事务期间 Supavisor 会把连接钉住，
  所以事务模式（6543）行为一致；
- 连接池大小：服务端默认 10（`MCS_WEB_DB_POOL_MAX`），免费档够用。

拿到的串形如：

    postgresql://postgres.<项目ref>:<你的数据库密码>@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres

把 `<你的数据库密码>` 换成第 1.1 步生成的那个（密码里有 `&`、`#`、`?`、空格等字符时要
[百分号编码](https://en.wikipedia.org/wiki/Percent-encoding)）。**判断标准很简单：主机名里必须有 `pooler`**。

**填完密码先在本机跑一次自检**，再去 Render——它把最容易错的那几件事（占位符没换、ref 写错、
用了直连地址、缺 TLS、没有建表权限）一次说清，省掉一轮"Render 起不来、日志里只有一句英文错误"：

    cd mcs-web
    $env:DATABASE_URL='（把上面那串完整粘进来）'
    node scripts/check-db.mjs

看到 `✓ 连接成功` 与 `✓ 有建表权限` 就对了（它只读，加一次权限查询，不改任何数据）。

### 1.5 记下你的用户 id

部署完先用 GitHub 登录一次，然后到 `Authentication → Users` 复制你那行的 **UID**，
填进 `MCS_WEB_AUTH_ADMIN_IDS`（管理员按认证服务的用户 id 指定，不是"第一个注册的人"）。

## 2. Render：起服务

1. <https://render.com> → New → **Blueprint** → 选你的仓库（仓库根有 `render.yaml`）。
2. Render 会按 `render.yaml` 建一个 Web Service，并把标了 `sync: false` 的变量列出来问你。
   逐个填：

| 变量 | 值 |
|---|---|
| `MCS_WEB_PUBLIC_ORIGIN` | `https://<你的站点域名>`（Render 分配的形如 `https://mcs-web.onrender.com`） |
| `MCS_WEB_ALLOWED_HOSTS` | 同上域名（**不含** `https://`），例如 `mcs-web.onrender.com` |
| `DATABASE_URL` | 第 1.4 步的连接串 |
| `MCS_WEB_AUTH_URL` | 第 1.1 步的 Project URL |
| `MCS_WEB_AUTH_PUBLISHABLE_KEY` | 第 1.1 步的 publishable key |
| `MCS_WEB_AUTH_ADMIN_IDS` | **先填占位值** `bootstrap`，见下面的「先有鸡还是先有蛋」 |

`MCS_WEB_AUTH_SESSION_KEY` 由 Render 随机生成（32 字节 base64），**不要手填、不要外传**：
它是会话 Cookie 的加密密钥，换了它等于让所有人重新登录。

### 先有鸡还是先有蛋：管理员 UID 怎么填

管理员**必须**至少配一个用户 id，否则服务按设计**拒绝启动**；可你的 UID 要等第一次
GitHub 登录之后才会出现在 Supabase 里。所以顺序是：

1. 部署时 `MCS_WEB_AUTH_ADMIN_IDS` 先填一个占位值（比如 `bootstrap`）——它不是一个真实用户，
   只是让"至少有一个管理员"这条检查通过；
2. 站点起来后用 GitHub 登录一次（这时你是**普通用户**，站点功能都能用，
   只有入库 / 发布 / 备份恢复这些管理员入口暂时不可见）；
3. 到 Supabase → `Authentication → Users`，复制你那行的 **UID**；
4. 回到 Render → Environment，把 `MCS_WEB_AUTH_ADMIN_IDS` 改成那个 UID，保存（会自动重启）；
5. 刷新页面，管理员入口出现。

> 为什么不做成"第一个注册的人自动成为管理员"：那等于把管理员身份交给任何一个先到的人。
> 显式配置多花两分钟，但不会出现"陌生人成了站点的管理员"。

3. 部署。观察日志，出现这些行即正常：

```
MCS Web 已启动：http://0.0.0.0:<port>
本体版本：sha256:…
数据库：PostgreSQL（<host>/<db>）
```

> 看到「启动失败」**先读那句话**：公网模式的自检会在缺 `DATABASE_URL`、
  缺账号配置、`publicOrigin` 不是 https、`allowedHosts` 为空时拒绝启动。
  这是设计，不是故障。

## 3. 上线验收（逐条做，别跳）

| # | 做什么 | 期望 |
|---|---|---|
| 1 | 隐身窗口打开 `https://<域名>/` | 首页正常，**不弹登录** |
| 2 | 打开 `/nodes` 与任一节点页 | 公共本体可读（232 个节点） |
| 3 | 打开 `/profile` | 显示「请先登录」，不是空白也不是报错 |
| 4 | `/login` → GitHub 登录 | 回到站点，页头出现你的邮箱 |
| 5 | 新建一个档案并写一条学习事件 | 成功，刷新后还在 |
| 6 | 退出，再用另一个 GitHub 账号登录 | **看不到**上一个账号的档案（越权一律 404） |
| 7 | 用第二个账号直接访问第一个账号的档案 URL | 404（不是 403、不是能读到） |
| 8 | Render 里手动 Restart 服务 | 重启后档案与登录状态**都还在**（这条验的就是 PostgreSQL） |
| 9 | 浏览器地址栏改成 `http://` 访问 | 会被平台跳回 https；http 下登录走不通是预期的 |

第 6、7、8 条是这一轮的重点：**数据隔离**与**重启不丢**。

## 4. 备份与恢复

- 公网模式（PostgreSQL）的备份是**逻辑备份**：`POST /api/v2/backup`（仅管理员）
  会在 `backupDir` 写出一份整库 JSON。
- 恢复：`POST /api/v2/restore`，body `{ "backup": "<备份目录下的那个文件>" }`，
  整库回填、失败整体回滚。
- **容器本地磁盘会随实例销毁**，所以 Render 上的 `backupDir` 是临时的：
  要长期保留就把备份文件下载走，或用 Supabase 自带的数据库备份。

## 5. 这一版明确没有的东西（写在这里，免得被误读成"已经全了"）

1. **邮箱注册 / 找回密码**：如实回 503；登录只有 GitHub。
2. **DeepTutor 辅导**：没有配置时为"未连接"，页面如实显示，不伪造可用。
3. **内容入库 / 发布 / 备份恢复**：只有管理员能调；公开站点上普通用户看不到入口。
4. **免费实例会休眠**：长时间没人访问后第一次打开要等十几秒冷启动。
5. **容器本地 SQLite 只用于编写库**（草稿等管理员状态），学习数据在 PostgreSQL。
6. Dockerfile **未在本机构建验证**（本机没有 docker）；用它的平台请先 `docker build` 一次。

## 6. 另一条路：Hugging Face Spaces（不需要境外卡）

适合「没有可用境外信用卡」的情况。免费档：2 vCPU / 16 GB，闲置约 48 小时后休眠，
首次访问叫醒要等几十秒。**注意 `huggingface.co` 主站在大陆被墙**，
注册、建 Space、填 secret 都要挂着梯子做；但建好之后的站点域名 `<用户名>-<space名>.hf.space`
是可直连的（实测 TCP 443 通）。

### 6.1 建 Space

1. 挂梯子 → <https://huggingface.co/join> 注册（邮箱即可，不需要卡）；
2. <https://huggingface.co/new-space>：
   - **Space name**：`mcs-web`（记住它，最终域名要用）
   - **License**：`mit`
   - **Select the Space SDK**：**Docker** → **Blank**
   - **Space hardware**：**CPU basic · 2 vCPU · 16GB · FREE**
   - **Visibility**：Public
3. 建好后把 Space 的地址发出来，形如 `https://huggingface.co/spaces/<用户名>/mcs-web`。

### 6.2 把代码推上去

Space 仓库要满足两件与 GitHub 不同的事：

1. **根目录的 `README.md` 必须带元数据**（`sdk: docker` 与 `app_port`），
   否则 Space 不知道拿什么跑、也不知道监听哪个端口；
2. **Dockerfile 必须在根目录**（我们已经有了，且 `ENV PORT=8080` 与 `app_port: 8080` 对齐）。

所以推送用的那份 `README.md` 在开头多这几行（**GitHub 那份不加**，否则仓库首页会多出一段 YAML）：

    ---
    title: MCS Web
    emoji: 🧮
    colorFrom: indigo
    colorTo: purple
    sdk: docker
    app_port: 8080
    pinned: false
    ---

推送目标：`https://huggingface.co/spaces/<用户名>/mcs-web`（HTTPS 推送要一个
**Write** 权限的 Access Token：Settings → Access Tokens；SSH 推送则把公钥加到
<https://huggingface.co/settings/keys>）。

### 6.3 填 8 个 secret

Space → **Settings → Variables and secrets → New secret**（全部选 Secret，不要 Variable）：

| 名字 | 值 |
|---|---|
| `MCS_WEB_PUBLIC_ORIGIN` | `https://<用户名>-mcs-web.hf.space` |
| `MCS_WEB_ALLOWED_HOSTS` | `<用户名>-mcs-web.hf.space`（不带 `https://`） |
| `DATABASE_URL` | Supabase 的 Session pooler 连接串（含密码） |
| `MCS_WEB_DB_SSL` | `require` |
| `MCS_WEB_AUTH_URL` | `https://<项目ref>.supabase.co` |
| `MCS_WEB_AUTH_PUBLISHABLE_KEY` | `sb_publishable_…` |
| `MCS_WEB_AUTH_SESSION_KEY` | 32 字节随机数的 base64（`node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`） |
| `MCS_WEB_AUTH_ADMIN_IDS` | 先填 `bootstrap`，首次登录拿到 UID 后再改 |

其余变量（`MCS_WEB_HOST`、`MCS_WEB_PUBLIC_MODE`、`MCS_WEB_AUTH_MODE`、
`MCS_WEB_AUTH_EMAIL_ENABLED`、`MCS_WEB_TUTOR_ENABLED`、`PORT`）**镜像里已经设好**，不用重复填。

改完 secret 后 Space 会自动重启；日志里出现 `MCS Web 已启动` 即成功。

### 6.4 之后

与第 3 节的验收清单相同，只是把域名换成 `https://<用户名>-mcs-web.hf.space`；
Supabase 的 `Authentication → URL Configuration` 里，Site URL 与 Redirect URLs
也要用这个域名（Redirect 要加 `https://<用户名>-mcs-web.hf.space/api/v2/auth/callback`）。

### 6.5 这条路的已知限制

1. 免费 Space 闲置约 48 小时休眠，醒来要等几十秒；
2. 容器磁盘是临时的——学习数据在 Supabase，编写库（草稿）会丢，这对公开站点无影响；
3. 管理界面（填 secret、看日志）都在被墙的主站上，改配置要挂梯子；
4. 证书重放要 Python——镜像里装了（`Dockerfile` 里 `apt-get install python3`）。

## 7. 第三条路：本机自托管 + Cloudflare 隧道（不需要任何境外账号）

用于「没有境外卡、Hugging Face 又上不去」的情况。实测（2026-10-05）在杭州的移动网络上
端到端可用：隧道建立、公网访问返回 200、GitHub 登录跳转追到 `github.com/login/oauth/authorize`。

做法：`cloudflared tunnel --url http://127.0.0.1:<端口>` 给出一个 https 地址，
站点以**公网模式 + 本地 SQLite** 跑在自己机器上；登录仍走 Supabase。

### 7.1 为什么可以在这条路上用本地 SQLite

`server/deployment.mjs` 默认拒绝「公网模式 + 本地 SQLite」——容器平台上本地文件会随实例消失，
学习记录不是缓存。但**自己的机器就是那块持久磁盘**，所以加了一个**必须显式打开**的例外：

    MCS_WEB_ALLOW_LOCAL_DB=1

默认关闭意味着误配到容器平台的部署仍然起不来，而不是悄悄跑起来再丢数据。

### 7.2 需要的环境变量

除第 2 节那批之外，这条路上多两个：

| 变量 | 值 | 作用 |
|---|---|---|
| `MCS_WEB_ALLOW_LOCAL_DB` | `1` | 显式允许公网模式用本地 SQLite |
| `MCS_WEB_DB`（可选） | 独立文件路径 | 把公网实例的数据与本机工作台**物理隔离** |

`MCS_WEB_PUBLIC_ORIGIN` 与 `MCS_WEB_ALLOWED_HOSTS` 要填**隧道给的那个域名**（每次重启都会变）。

### 7.3 代价

1. 机器要一直开着、启动脚本的窗口不能关；
2. 快速隧道地址每次重启都变（想固定：域名 + 命名隧道）；
3. 数据只在这台机器上，要自己定期备份；
4. Supabase 的 `Redirect URLs` 加一条 `https://*.trycloudflare.com/**` 即可免去地址变动之扰。

### 7.4 验收要点（这条路同样适用）

- 未登录访问 `/api/v2/profiles` 必须 **401**（不是 200 空数组，也不是 403 泄露存在性）；
- Host 不在白名单时本机直连必须 **403**；
- 伪造回调 `?state=fake&code=fake` 必须 **401**；写接口无 CSRF / 错 Origin 必须 **403**；
- 公网实例与 `runtime\*.sqlite3`（本机工作台）必须**互不影响**。

以上四条 2026-10-05 已实测通过（见 `VALIDATION.md` 第七十九轮）。
