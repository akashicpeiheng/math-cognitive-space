# 网络视图：缩放、混合笔记与私人关系

实现及验收日期：2026-10-15。入口是「知识网络」。这些功能产生私人记录 E 和派生视图 D；导入、保存和验证不会改写公共本体 M，也不产生掌握确认。

## 先浏览，再解释

缩放到 `0.55` 以下，卡片变为圆点；放大到 `0.65` 以上恢复卡片。中间保留当前形态。圆点沿用卡片中心、同一套节点和连线坐标，切换不触发布局。节点拖动、右键、长按推荐、双指缩放、连接备注、三种排法和路线回放继续使用原来的入口。

鼠标停留约 250ms 或键盘聚焦节点后出现介绍，可将指针移入浮层；Esc 和拖动收起。触屏选中节点后，在节点详情中阅读同样的解释。重排使用约 220ms 的有限过渡，系统减少动态效果时立即更新；静置后没有持续运行的布局动画。

介绍分别呈现两类信息：数学意义优先取公共节点已经登记的动机，缺少时取其正文的明确章节；笔记也只取动机、数学意义、理论定位等章节的明确文本，并列明出处。当前视图的前置、后续、关联及笔记引用则由当前可见节点与连接筛选计算。连接多不代表数学重要。没有来源的数学意义显示「尚未整理」，可另存本机私人补充。

## 混合网站节点与多个笔记库

在节点选择面板展开「节点来源与私人关系」，选择一个或多个已导入库，再选择网站节点或笔记；导入和更新仍在「我的笔记库」进行。网站数学节点、笔记引用、私人参考关联和私人声明的数学关系各自保留语义。

公共节点以本体 ID 和版本引用；笔记以存储位置、库 ID、文件 ID、库修订和文件 SHA-256 引用。标题相同不会合并，附件不会成为首版网络节点。Wiki 和 Markdown 链接复用笔记库解析，只有唯一且可用的笔记目标才形成引用边；歧义和断链显示数量。缺失库或文件保留节点引用，并提供恢复来源的入口。

「笔记关联数学节点」是私人参考关联。它和普通引用都不构成数学前置。自由布局接受所有来源；学习顺序沿用公共硬前置，笔记放在关联材料中；逻辑核心衡量的是当前图中的连接中心程度。

每图最多 2,000 节点，超限会提示。超过安全查询串长度时，节点集合放入 URL 片段，避免刷新时请求头过长。笔记解析在 Worker 中进行，缓存按文件内容哈希及链接目录签名区分；正文单独变化只重解析变化文件，文件新增、删除、改名或别名变化会重新解析受目录影响的引用。公共悬停详情按需读取，按本体版本、节点与语言缓存。

## 建立与复用私人关系

右键节点选择「建立私人关系」，选择另一端、关系类型，填写条件、理由和依据。「交换关系方向」会同时交换两端的形式材料，清除当前验证显示；保存修订后需要重新验证。

高级区域可填写受限语言的 JSON 形式表达、原文摘录和人工对应确认。公共端使用公共登记表达；笔记端必须绑定明确摘录及其文件哈希，不能将整篇笔记或私人陈述直接作为背景公理。私人关系在来源面板中可再次编辑、删除、导出或导入，在其他视图中复用；导入文件携带的“已验证”声明不会获得信任。

验证结果有三个独立部分：

| 部分 | 表达的事实 |
| --- | --- |
| 结构检查 | 类型、端点、方向、条件和声明的引用版本是否满足契约；本地检查不证明数学命题 |
| 数学判断 | 现有六类判定器对精确形式表达的判断；搜索失败、缺少形式化和不支持保持 `undecided` |
| 运行状态 | 完成、不支持、超时、取消或中断；超时和取消不等于反驳 |

服务端复用现有队列、配额与取消机制，生成并持久化绑定输入哈希的结果。六类入口是定义引用、放缩、等价、条件推导、实例和反例。原文对应的人工确认单独记录，机器证明通过不会自动勾选它；自然语言条件也不会自动成为机器前提，应在形式材料中明确表达。

`PROOF` 只覆盖通过检查器重放的精确目标及声明背景。`FINITE` 只覆盖报告列出的有限模型、完整运算表、背景公理、显式假设与选定公式，不是一般数学证明。首版私人关系的有限模型入口限于已有登记的有限群，任意笔记模型和未展开定义会保持未判定。其他不支持的表达同样如实保留未判定。

修改关系、命题绑定、笔记修订、文件内容或公共理论版本后，旧记录仍可查看，但不能作为新输入的当前结论。账号笔记原文由服务器核对摘录和版本；本机笔记正文不为机器验证而上传，服务器检查用户提交的形式表达及声明的哈希，原文的对应仍需用户确认。

## 保存、同步与隐私

新视图使用 `mcs-network/2` 快照，保存节点引用、来源、关系筛选、全部节点位置、手动位置、排法、锚点和相机。会话暂存、节点或笔记阅读后的返回、视图导出都保留这些信息。旧快照继续按公共节点视图读取。

本机笔记正文、私人关系及索引存放在浏览器 IndexedDB；含本机笔记节点的混合图默认保存本机。账号同步是单独按钮，明确标为「上传所用笔记库正文并同步」：先调用已有库上传流程，再映射账号库、文件和节点引用。机器验证只发送两端引用、选定摘录、关系及所填形式材料，界面中的私人库同步操作会上传所用库正文，两者的发送范围不同。

账号私人关系、验证与投稿使用 `private_network_records` 表，SQLite / PostgreSQL 共用按账号隔离、乐观修订锁、历史和备份恢复的实现，不依赖当前学习档案。公网游客可在本机编辑和检查结构；机器验证、账号同步及投稿需要登录。本机服务沿用本机身份。

## 投稿与管理员审阅

在关系编辑器预览公开标题、最小摘录、条件、理由、来源及形式材料；如果选择附带当前检查，预览同时显示证据状态和输入哈希。提交后固定这些材料及服务端取得的证据，后续笔记修改不会替换已提交版本。公共候选材料不携带自动生成的私人库地址或文件定位。

投稿状态包括待审、需补充、驳回、撤回和已发布；`staged` 表示已送入候选编写流程，并不表示发布。管理员在「关系投稿与审阅」选择全部投稿，把两端映射到公共节点或建立独立候选节点。两个端点均为新候选时，分别审阅、验证和发布节点，再通过现有编写台发现、重放并发布关系。私人检查不会直接成为公共本体证据。

最后填写实际发布的公共关系 ID，并单独确认形式表达与公开摘录的对应。服务器核对当前发布本体中的端点、类型和已重放证据；缺少真实发布关系时拒绝标记已发布。失败保持旧公共本体生效。

## 接口与实现入口

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v2/me/network-relations` | 账号私人关系库 |
| `PUT/DELETE /api/v2/me/network-relations/:id` | 按 `baseRevision` 修改或删除 |
| `GET /api/v2/me/network-relations/export` | 导出本账号私人关系与检查 |
| `POST /api/v2/network-relation-checks` | 提交所选形式材料 |
| `GET/DELETE /api/v2/network-relation-checks/:id` | 读取或取消本人任务 |
| `GET/POST /api/v2/me/relation-submissions` | 本人投稿与固定材料 |
| `DELETE /api/v2/me/relation-submissions/:id` | 按修订撤回 |
| `GET /api/v2/authoring/relation-submissions` | 管理员审阅队列 |
| `PATCH /api/v2/authoring/relation-submissions/:id` | 审阅、映射、候选编写及核对已发布关系 |
| `GET /api/v2/ontology/scale` | 四层尺度登记（只读迁移投影；不改本体版本，不写档案） |

尺度视图（2026-10-17）的登记、可见性、自动合拢与验收边界另见[尺度视图记录](尺度视图-2026-10-17.md)。`scales` / `scaleNodes` / `split` / `merge` 是**视图状态**：随 URL 与会话暂存恢复，命名视图保存进 E；展开/合拢本身不产生学习事件。

统一契约在 `shared/network-workspace.mjs`；来源适配和索引在 `web/src/network-workspace.ts`、`useNetworkWorkspace.ts` 及 `network-index-worker.ts`；画布继续使用 `NetworkPage.tsx`。服务器存储、接口和机器检查分别在 `server/network-store.mjs`、`server/network-api.mjs`、`core/network-check.mjs`。

实际执行的测试、性能观测和未验证范围见[网络视图验收记录](网络视图验收记录-2026-10-15.md)。
