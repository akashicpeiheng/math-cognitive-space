## 依赖与偏好的分工

`DEF`：依赖决定可行顺序；显式需求和兴趣决定可行顺序中的优先级。
例如 A、B 联合支持 C 时，可以选择 A → B → C 或 B → A → C，C 始终在两者之后。

`core/learning-plan.mjs` 调用现有 `makePlanner` 选择行动及来源，保持行动输入的 AND
和替代行动的 OR 语义。对各个候选分别补齐已登记的硬前置，再调用同一规划器；不会把
不同替代方案的要求合并为必需知识。建议骨架只表示一条可展开的教学方向，并非所有证明
方案的必需集合。

`shared/learning-plan.mjs` 对所选方案的规范化事件图做拓扑排序。前置已满足的事件按以下
优先级比较：有效手动顺序、实际主线事件、学科兴趣顺序、上一事件的学科连续性、学法、
直接解锁的主线事件数、稳定事件标识。重复事件保留独立实例；共享来源只安排一次。

支线由学习者主动加入，默认排在近期主线里程碑之后。提前、延后、选为下一步必须通过
完整排列和所有事件依赖的检查；失败保留原顺序，并列出阻止移动的具体步骤。
已确认节点不再作为待学任务。恢复推荐顺序只清除手动排列，不改变知识状态。
主目标确认后，主动加入且未完成的支线继续展开。

`ILLUSTRATION`：近期显示 3–5 步，最多三个支线目标，选择深度不超过五的主线里程碑。
这些是交互设计默认值，学习效果尚需真实使用验证。规划有八事件、5000 候选、六个里程碑
尝试及六次硬前置重规划的边界；搜索截断不解释成目标一般不可达。成环、无法解析的目标、
无可行近期方案均保留错误或未知状态，并提供核对背景、重新探索和重新载入入口。

## 数据与接口

`LearningPlanState` 保存主目标、按优先顺序排列的学科兴趣、主动加入的支线、学习节奏、
学法和手动顺序。`LearningPlanView` 另含修订号、更新时间。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v2/profiles/:id/learning-plan` | 读取档案方案；无新设置时回退最早声明的有效单元方向 |
| `PUT /api/v2/profiles/:id/learning-plan` | 携带 `baseRevision`，原子保存；冲突 409；主目标复用方向表与 goal 事件 |
| `POST /api/v2/learning-plan-preview` | 在有界任务队列计算 D；带档案 id 时校验归属 |
| `GET /api/v2/learning-plan-preview/:jobid` | 查询预览；含档案信息的任务只能由创建账号读取 |
| `DELETE /api/v2/learning-plan-preview/:jobid` | 取消任务；沿用相同归属校验 |

SQLite、PostgreSQL 都通过幂等建表迁移增加 `learning_plans`，每档案一行。
修订号通过带条件的 INSERT / UPDATE 校验，保存主目标与方向声明处于同一事务。
档案导入导出、SQLite 物理备份和 PostgreSQL 逻辑备份恢复均包含方案。
旧导出和旧备份没有方案字段时仍可恢复。

手动顺序绑定本体版本与规范化事件图哈希，步骤使用事件结构导出的稳定标识。
本体、已确认知识或目标变化后重新核对；失效记录保留并明确提示，使用新的推荐顺序。
开始学习、路线、我的学习、节点页共用设置；路线阅读采用有效顺序。

访客草稿使用 `mcs-learning-plan-guest-v1`，采用到所选档案后可跨浏览器继续。
旧 `mcs-start-preferences-v1` 和 `mcs-direction-decisions-v1:<profileId>` 缓存原样保留；
旧兴趣、节奏、学法可作为未设置档案的回退，已有服务端方案优先。

## 状态边界与检查入口

`DEF`：公共本体是 M，档案方案和确认记录是 E，预览路线是 M＋E 派生的 D。
当前可学集合只依据已确认知识。未来预览可使用未确认背景与前面步骤的产出，但明确标为
条件；选择目标、加入支线、调整顺序、浏览内容均不产生知识确认。

`FINITE`：以下自动检查只验证所列有限输入，不是一般证明，也不证明学习效果。

| 检查 | 覆盖 |
| --- | --- |
| `tests/learning-plan.test.mjs` | 并行换序、AND/OR、候选独立硬前置、共享来源、支线、非法提前、重复事件、成环、真实六方向与条件预览 |
| `tests/learning-plan-store.test.mjs` | SQLite、真实 PostgreSQL 语义的 PGlite：修订冲突、隔离、导入导出、旧数据、备份恢复、主目标声明不确认知识 |
| `tests/auth.test.mjs` | 档案与预览任务归属、访客公共预览、CSRF |
| `tests/learning-guide.mjs` | 两种入口、搜索、跳过偏好、背景动作、支线、非法移动、阅读、跨浏览器继续、四页面共用、中文英文、1440 / 768 / 390px |
| `tests/learning-guide-i18n.mjs` | 搜索截断有完整结果入口；未译标题、背景和依赖明确标注中文回退 |

交付运行 `npm run build`、`npm run check`、`npm test`、`npm run check:i18n`。
英文 UI 检查可运行 `node scripts/i18n-ui-scan.mjs --path /en/start --path /en/plan --path /en/profile --strict-attrs`。
浏览器验收截图位于被版本控制忽略的 `runtime/learning-plan-qa/`，测试数据库全部位于临时目录。

回看问题：学习者是否能解释第一步与主目标的关系？为何提前失败？长期目标展开到里程碑后，
是否仍能理解它将通向哪里？这些问题需要实际使用反馈。

思想：先把依赖约束固定，再把兴趣转成可解释的次序。方法：通过候选独立补前置、事件拓扑
排序和条件预览，把方向探索收束为可执行的下一步。
