# Lean 登记与重放

首版登记两个独立验证对象：群案例的左乘单射片段与理论命题 8.8 的四条闭包性质。数学来源、逐条件对照和证明概括见 [Lean 工程说明](../../mcs-foundations/lean/README.md)。机器检查、原文对应审阅和覆盖范围是三个判断；当前人工对应审阅为 `pending`。

实际工具链、报告摘要、回归与发布核验见 [首版验收记录](LEAN-验收记录.md)。

## 准备和部署

安装工具链 `leanprover/lean4:v4.34.1`。在 `mcs-foundations/lean/` 使用已提交的 `lake-manifest.json` 准备固定依赖，执行 `lake exe cache get`、`lake --no-cache build MCS`。锁文件中的 mathlib 为 `d13f23b723b8a846827a245b89c10fc7d3f11612`。此步骤允许联网，网页重放期间不准备或升级依赖。不要在上线时自动更新锁文件。服务只执行完整原生工具链，跳过可能自动下载的 elan 代理；环境变量应指向实际工具链的 `bin/`。版本按完整版本号核对，`4.34.10` 与预发行版不匹配。

在 `mcs-web/` 执行：

```powershell
node scripts/lean.mjs seal
node scripts/lean.mjs publish-report
node scripts/lean.mjs ready
$env:MCS_WEB_REQUIRE_LEAN = '1'
npm run check
npm test
```

`seal` 是维护操作，记录输入，不是证明。`publish-report` 会真实运行检查链后保存当前报告，同时保留带时间与哈希的历史报告。任何源码、原文、依赖锁或检查入口修改后，都须重新核对输入、检查并发布报告；人工审阅字段不能由机器通过自动填成已审阅。`ready` 是部署时的 Lean 就绪门禁，环境和当前已发布报告须同时就绪。

人工对应审阅还须填写实际审阅者、时间、`reviewedSourceHashes`（除登记文件自身以外的源文件摘要）及 `reviewedOriginalHashes`。缺记录或摘要不符仍显示待复核。报告的 SHA-256 校验检测意外损坏，不是数字签名；已发布报告的信任仍来自审核过的仓库版本，个人任务报告来自当前服务的实际运行。

当前单进程自托管路线仍通过既有发布包导出及运行副本切换部署。导出包包含 Lean 源码、登记、锁文件、输入摘要和维护发布的报告，跳过 `.lake/`、`.lean-tools/`、临时工作目录及用户数据库。运行副本要在切换前独立准备依赖并运行 `ready`；不能复制开发机用户任务历史充当公开报告。Linux 和 Windows 均可使用显式 `MCS_WEB_LAKE`、`MCS_WEB_LEAN` 指定工具链二进制。缓存所在位置须可读，临时工作目录须可写。

`MCS_WEB_LEAN_ENABLED=0` 关闭重放，保留公开材料与历史报告。未安装工具链时亦可阅读材料，能力接口明确返回不可重放。关闭开关是界面和 API 的回退，不删验证历史。当前队列适用于一个服务进程，多副本调度未实现。

Windows 默认在 `mcs-web/runtime/lean-check/` 创建临时任务目录，Linux 默认使用系统临时目录；可用 `MCS_WEB_LEAN_WORK_DIR` 指定服务账号可写的目录。依赖缓存只读连接到临时目录，清理先断开连接，随后删除任务自己创建的目录，不删除依赖。

正常服务关闭会等待任务中断并终止检查进程树。Windows 本机停止脚本和现有公网守护的强制停止、健康失败重启也使用 `taskkill /T`，避免只结束 Node 而留下检查子进程。强制结束服务后的未完成记录在下次启动时标为 interrupted。

成功与检查拒绝报告保留编译器日志；取消、超时及环境异常任务保留阶段、诊断、输入摘要与时间。存储另记诊断日志摘要，页面可下载未产出证明报告的任务诊断，不能把它当成通过证书。

## 接口与权限

| 接口 | 权限与行为 |
|---|---|
| `GET /api/v2/lean/capabilities` | 公开；工具链、登记版本、固定依赖、封存状态与队列容量 |
| `GET /api/v2/lean/registrations/:id` | 公开；原文陈述、范围、对应说明、源码、发布报告与过期状态 |
| `POST /api/v2/lean/jobs` | 本机用户或公网登录账号；请求仅含 `evidenceId`、`ontologyVersion` |
| `GET /api/v2/lean/jobs/:id` | 本人任务；跨账号及未知任务均返回 404 |
| `DELETE /api/v2/lean/jobs/:id` | 本人取消；继承现有 Origin 和 CSRF 检查 |

示例输入为 `{"evidenceId":"ev-lean-group-injective","ontologyVersion":"当前本体版本"}`。不得传代码、路径、命令或依赖 URL；附加字段被拒绝。任务 ID 保存在按账号区分的浏览器会话存储中，刷新可恢复进度。源码和结果可在节点页及研究页阅读；理论命题无须伪造知识节点。

## 检查链、限额与记录

命令行和 API 共用 `core/lean.mjs`：验证工具链及 Git 依赖提交和工作树，捕获不可变源码快照，在独立目录构建，再从实际环境核对包装定理的目标与传递公理依赖。检查策略 `mcs-lean-check/2` 只用 Lake 取得必要的编译环境，然后让 Lake 退出，原生 Lean 按依赖顺序重新编译全部六个项目模块；不会复用上一次任务的项目产物。编译、重放和审计使用 `lean -j 1`，限制单个任务的工作线程。环境捕获仅包含明确列出的编译变量，不把环境值写入报告。

内核重放在一个原生 Lean 进程中顺序调用工具链 `LeanChecker` 的官方 `replayFromImports`，依次检查定义、目标、两份证明和包装定理模块。这与 `leanchecker` 使用同一检查函数，减少重复扫描和启动开销，同时避免驻留 Lake 父进程及并行加载多份完整导入环境。每个模块成功后留下标记，缺失、重复或乱序均不能判为通过；报告记录实际命令和标记，并绑定检查入口及导入的 `LeanChecker.olean` 摘要，结束前再核对依赖与工具链摘要。旧策略报告仍可作为历史读取，不能充当当前策略的通过结果。

八个固定目标、逐目标核对和传递公理审计保持原范围。仅允许 `propext`、`Classical.choice`、`Quot.sound`。缺报告、损坏报告、缺目标、非零退出码、`sorryAx` 或额外公理均不能判为通过。标准公理本身仍属于可信基础；此流程不声称 Lean 检查器已被独立形式验证。

任务重放检查项目模块，导入的固定版 mathlib 环境是该重放的基础，不把它标成独立外部内核复核。维护阶段可额外执行 `lake env leanchecker --fresh MCS.Verified`，从空环境重放全部传递导入；该完整复核可能超过网页的 120 秒任务限额，应单独记录，不能偷偷提高网页时限或把超时判成通过。

默认并发 1、排队 20，每账号最多 1 运行及 1 排队。执行超时 120 秒、累计输出上限 4 MiB。取消、超时、输出超限和正常服务退出会等待整个检查进程树停止。未完成任务在重启后标记中断，须由用户重新发起；不会自动重跑或伪报完成。

SQLite/PostgreSQL 的 `verification_runs` 独立保存归属、不可变输入摘要、状态、报告、日志摘要与时间，纳入原有数据库备份恢复。排队与运行期间保存输入快照，结束后移除快照正文。它是 D 层验证历史，不生成学习事件、不提升掌握状态、不添加硬关系、不回写公共本体 M。网页中的已发布报告与本次个人重放结果分开显示；旧输入的通过只保留为历史证据。

## 验证入口与边界

- `npm run test:lean`：结构、封存、队列、双驱动、真实进程树；工具链就绪时还运行真实证明及负例。
- `node tests/lean-page.mjs`：中英节点/研究页、真实重放、报告下载、窄屏及 M/E 不变。
- `node --test tests/auth.test.mjs`：公网匿名、登录、来源/CSRF、跨账号隔离，真实重放不改变学习状态。
- 设置 `MCS_WEB_REQUIRE_LEAN=1` 后，缺少真实环境会失败，不能跳过后声称完整验收。

完整 Cayley 定理、在线任意代码、自动形式化全部笔记、一般 HOL—Lean 翻译证明和教学收益保持未完成或 NOT-CLAIMED。公网生产域名及真实身份提供商的发布验收须在运行副本完成，隔离测试服务的通过不代表生产部署已更新。
