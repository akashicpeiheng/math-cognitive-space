## 0. 已核验的前置事实（`FINITE`）

2026-10-04 用探针（`tmp/probe/`）核对，三条都通过：

1. **Node 能造出 kernel.py 接受的证书**：`{format:'mcs-nd-subset/1', theory, proofs, target}`
   经 `python mcs-foundations/validation/certification/kernel.py <file>` 返回 `status: "passed"`。
2. **哈希口径一致**：`kernel.digest(x)` = `sha256(json.dumps(x, ensure_ascii=True,
   separators=(',',':'), sort_keys=True))`，Node 侧按同一序列化重算，三个哈希
   （theory / proof / bundle）**逐字节相同**。
3. **认证公式与对象项的区分是硬性的**：`hypotheses` 的值必须是认证公式；
   直接把对象项 `['v','h','o']` 放进去会被拒（`unsupported certification formula: v`），
   必须写成 `['eq', ['v','h','o'], ['logic','true']]`（记作 `B(t)`）。

**检查器的事实边界（照抄，不得含糊）**：

- 规则白名单只有：`assume`、`h_axiom`、`theory`、`definition`、`theorem`、
  `imp_i`、`imp_e`、`and_i`、`and_l`、`and_r`、`refl`、`eq_e`、`all_i`、`all_e`、`ex_i`、`ex_e`。
  **没有** `or_i` / `or_e` / `false_e` / 经典反证 / β 规则的独立入口。
- 认证公式只允许 `eq / false / and / or / imp / all / ex`；`or` 可表示但**无规则**，
  因此首版语言**不接受析取**。
- `theory.axioms` 的每条必须是**闭公式**，且 `theory` 规则步骤要带
  `witness = digest(axiom)`。这是「不能把待证结论偷偷塞进公理」的机制保证。
- `theory.definitions` 只支持 `kind: 'term'`，项必须是**旧语言闭项**（无自由变量）。
- `MAX_STEPS = 2000`（整包所有 proof 的步骤之和）。
- **`lift` 里的抽象不是项参数**（`term_sub` 不动它），β 只能走 `h_axiom` 的
  `abstraction` 模式。**这是首版证明搜索的核心约束**，见 §4。

## 1. 受限形式语言（版本 `mcs-formal/1`）

### 1.1 类型

```
type := ATOM | type '->' type          -- 右结合，'->' 优先级最低
ATOM := 'o' | [A-Za-z][A-Za-z0-9_]*
```

`o` 是真值类型，必须存在。等价写法：`o`、`bool`、`Prop`（别名 → `o`）；
`Nat`/`ℕ` → `N`；`Real`/`ℝ` → `R`；`Set`/`集合` → `Set`；`Group`/`群` → `Group`；…

### 1.2 项（对象语言，term）

```
term := IDENT | IDENT '(' term,* ')' | 'λ' binder+ '.' term | 'lam' binder+ '.' term
      | '(' term ')' | 'let' IDENT '=' term 'in' term        -- let 在解析期消去
binder := IDENT (':' type)?
```

- 应用**左结合**：`f a b` = `App(App(f,a),b)`。
- λ 可以多绑定：`λx y. t` = `λx. λy. t`；带类型注释 `λ(x:R). t`。
- `let x = t in u` 在解析期展开为 `(λx. u) t` 的**替换结果**（不做 β 步，直接代入）。
- 常量名与变量名同名时：**绑定的 λ 变量遮蔽常量**；同一自由语境里同名异类型 → 拒绝。

### 1.3 公式（认证语言，formula）

```
formula := 'true' | 'false'
         | term '=' term
         | formula ('∧'|'/\'|'and') formula
         | formula ('⇒'|'->'|'=> '|'imp') formula
         | formula ('⇔'|'<=>'|'iff') formula            -- 展开为 (a⇒b)∧(b⇒a)
         | ('∀'|'forall') binder+ '.' formula
         | ('∃'|'exists') binder+ '.' formula
         | '(' formula ')' | '¬' formula                -- ¬a 展开为 a ⇒ false
```

**不接受**：析取 `∨/or`（内核无规则）、经典反证、任意高阶合一、集合论符号、
`∑/∏` 这类未登记记号。遇到就报 `unsupported`，并在错误里写清是哪一条。

### 1.4 规范化（parse → canonical）

1. 别名归一（§1.1、§1.3 的双写）。
2. `iff` 展开为合取、`¬` 展开为蕴含 `false`、`let` 消去。
3. **变量重命名（α 规范）**：每个绑定量词/λ 的变量按出现次序重命名为
   `z0, z1, z2, …`（避开该表达式中已用的名字）。自由变量**保留原名与类型**。
   → 因此「绑定改名」与「不随意重排自由参数和量词」同时成立：改名不改变规范形式，
   量词顺序改变则规范形式改变（可判为不同命题）。
4. **合取/蕴含嵌套扁平化**：`a ∧ b ∧ c` 解析成右结合 `a∧(b∧(c))`；证成侧可重排，
   规范形式**不重排**（重排要另出证书，不允许按"显然"接受）。
5. 类型注释缺失时按上下文推断；推断不出 → `undeclared-type` 错误，带位置。

### 1.5 定义（透明缩写）

```
definition := 'def' IDENT (':' type)? '=' term
```

- 新定义**只能引用已有定义/符号**；直接或间接循环 → 错误 `cyclic-definition`，
  错误里给出环上的名字序列。
- 定义只是**展开规则**：`Name ≜ term`，且 `term` 中不出现 `Name` 自身。
- 在证书里，定义以 kernel 的 `theory.definitions`（`kind:'term'`）登记，
  展开靠 `definition` 规则步骤；**定义不能当公理用**。
- 首版**不提供新增基本公理的入口**。

### 1.6 `formalSpec` 数据形状（共享类型）

```jsonc
{
  "specVersion": "mcs-formal/1",
  "node": "group:group-axioms",         // 引用某个节点或候选草稿标识
  "nodeVersion": "1",                    // 绑定的节点版本（草稿用 draft 标识）
  "background": "bg:core/1",             // 背景理论标识
  "theoryVersion": "1",
  "declarations": [
    { "name": "G", "type": "Set", "role": "object", "label": "群的对象集" },
    { "name": "mul", "type": "G -> G -> G", "role": "function" },
    { "name": "P", "type": "G -> o", "role": "predicate" },
    { "name": "h", "type": "o", "role": "proposition" }
  ],
  "definitions": [
    { "name": "abelian_group", "type": "(G->G->G) -> G -> (G->G) -> o",
      "source": "λmul e inv. group_concept(…) ∧ ∀a b. mul a b = mul b a" }
  ],
  "assumptions": [
    { "id": "A1", "source": "abelian_group(mul)(e)(inv)" }
  ],
  "statement": {
    "source": "∀a b. mul a b = mul b a",
    "kind": "formula"
  },
  "claims": [
    { "id": "C1", "source": "group_concept(mul)(e)(inv)", "role": "derived" }
  ],
  "references": [
    { "node": "group:group-concept", "version": "1", "specHash": "sha256:…",
      "kind": "definitionReference", "symbols": ["group_concept"] }
  ],
  "boundary": ["未展开：群公理模板的具体结构仍需逐项检查。"],
  "source": "人工登记：对照 data/cases/04-group.md 第 3 节",
  "hash": "sha256:…"                      // 规范化表达树的哈希
}
```

**规则**：

- `declarations[].name` 在该 spec 内唯一；与背景理论的常量名冲突时**拒绝**
  （避免「同名不同物」）。
- `statement.source` 必须解析为**认证公式**（类型 `o`）。
- `assumptions[].source` 同上；它们是**局部假设**，进证书的 `hypotheses`，
  绝不允许被写进 `theory.axioms`。
- `claims[].source` 行同。
- `references[].specHash` 指向被引用节点在该本体版本下的 `formalSpec.hash`；
  版本或哈希对不上 → `stale-reference`。

### 2.7 `core/formal/clauses.mjs` —— 定子句化

```js
// formula -> { clauses: [{ head, body: [atom], vars: [meta] }], goals: [atom] }
// atom := { kind:'pred', pred: term, args: [term] }   -- 恒为「谓词应用」形状
export function clausifyFormula(f, sig, { role: 'goal'|'fact' });
export function atomsOf(f);                             // 诊断用
```

编码约定（**这一层是"把 ND 翻译成定子句"的翻译函数**）：

| 公式形状 | goal 侧 | fact 侧 |
|---|---|---|
| `B(t)`（`t = true`） | 原子 `holds(t)` | 原子 `holds(t)` |
| `a ∧ b` | 两个子目标（都要证） | 两条子句 |
| `a ⇒ b` | 以 `a` 为假设证 `b` | 子句 `b :- a` |
| `a ⇔ b` | 两个蕴含，分别证 | 两条子句 |
| `∀x.φ` | 本征变量（fresh 常量），goal 为 `φ[c/x]` | 自由 meta 变量，子句为 `φ[?x/x]` |
| `∃x.φ` | 自由 meta 变量，goal 为 `φ[?x/x]` | 本征常量，子句为 `φ[c/x]` |
| `t₁ = t₂` | 原子 `eq(t₁,t₂)` | 原子 `eq(t₁,t₂)` |
| `false` | 不可证（`false_e` 未实现）→ `unsupported` | 不接受 |

### 2.8.1 `QueryProof`：搜索到证书之间的**唯一**桥梁

`search` 不直接生成 ND 步骤，它返回一棵查询树；`certificate.mjs` 把这棵树重建成
kernel 认的步骤序列。两个模块都只认这一种形状：

```jsonc
{
  "goal": ["eq", ["v","g","G"], ["v","h","G"]],   // 认证公式或对象项
  "rule": "axiom",                                  // 见下表
  "premises": [ /* QueryProof，顺序即 kernel 的 premises 顺序 */ ],
  "hypothesis": { "name": "equal_left_translations", "id": "h1" },  // rule=hypothesis
  "instance": { "schema": "abstraction", "term": ["lam","G",["b",0,"G"]] },  // rule=axiom
  "theoryAxiomId": "right_identity",                // rule=theory
  "definitionName": "const_seq",                    // rule=definition
  "lemmaId": "limit:constant-value#1",              // rule=lemma
  "eigen": ["v","z0","G"],                          // all_i 的 variable / ex_e 的 variable
  "discharge": "h1",                                // imp_i / ex_e 的 discharge 标签
  "term": ["c","unit"]                              // all_e / ex_i 的实例项
}
```

| `rule` | 对应 kernel 规则 | 必填字段 | `premises` 数 |
|---|---|---|---|
| `hypothesis` | `assume` | `hypothesis` | 0 |
| `axiom` | `h_axiom` | `instance` | 0 |
| `theory` | `theory` | `theoryAxiomId` | 0 |
| `definition` | `definition` | `definitionName` | 0 |
| `lemma` | `theorem` | `lemmaId` | 0 |
| `imp_i` | `imp_i` | `discharge` | 1 |
| `imp_e` | `imp_e` | — | 2（先蕴含、再前件） |
| `and_i` | `and_i` | — | 2 |
| `and_l` / `and_r` | `and_l` / `and_r` | — | 1 |
| `refl` | `refl` | — | 0 |
| `eq_e` | `eq_e` | `variable`、`context` | 2（先等式、再 `ctx[a]`） |
| `all_i` | `all_i` | `eigen` | 1 |
| `all_e` | `all_e` | `term` | 1 |
| `ex_i` | `ex_i` | `term` | 1 |
| `ex_e` | `ex_e` | `eigen`、`discharge` | 2 |

**装配出来的步骤还要过 `search` 的证明图检查**：步骤 id 唯一、依赖无环、
**所有提交步骤（含未用步骤）都要有限且闭合**（kernel 会遍历全部步骤）。

必须逐条核对：证书实际证明的**精确命题**（不是"跑通了"）、理论 id/版本/哈希、
节点版本、**实际开放假设**（自报与重算都要一致）、证书内没有偷偷加进 `theory.axioms`
的条目（比对背景白名单）。

### 2.11 `core/formal/judges/*.mjs` —— 五类关系判定器

```js
// 统一形状
export function makeJudge(kind, deps);                  // -> { kind, candidates(spec, ctx), confirm(candidate, ctx) }
export const RELATION_KINDS = ['definitionReference', 'hardGeneralization',
  'equivalentTo', 'conditionalDerivation', 'instanceOf', 'counterexampleTo'];
```

| 文件 | 关系 | 候选生成 | 确认 |
|---|---|---|---|
| `definition-reference.mjs` | `definitionReference` | 表达树里出现的已登记符号 | 版本 + 类型核对（不需证书） |
| `generalization.mjs` | `hardGeneralization` | 同背景、同参数类型的概念对 | 全称蕴含证书 |
| `equivalence.mjs` | `equivalentTo` | 同背景、参数**逐位类型相同**的概念对 | 双向蕴含证书或定义展开 |
| `derivation.mjs` | `conditionalDerivation` | 引理结论匹配 + 前提共同子集 | 联合输入的证书（保存全部前提） |
| `instance.mjs` | `instanceOf` | 已登记有限对象 × 概念 | 有限求值器全表检查 |
| `counterexample.mjs` | `counterexampleTo` | 候选蕴含 × 有限对象 | 满足背景与前提但不满足目标 |

**方向约定**：`hardGeneralization` 保存「一般概念 → 特殊概念」，
证据证明的是 `特殊 ⇒ 一般`；反向只作为**读法**，不重复产生第二份证据。

**两条禁令（写进代码）**：

1. 不对任意两个已证明的封闭定理自动生成 `equivalentTo`；概念等价比较必须保留共同参数与对象类型。
2. 推导证明用了某个前提，只登记**该份证明**的依赖，不宣称所有证明/所有路线都依赖它。

## 3. 发现运行的预算（可配置工程限制）

| 项 | 默认值 | 说明 |
|---|---|---|
| 候选上限 | 100 | 超出后**保留已完成结果**并列出未处理数量 |
| 单候选时限 | 8000 ms | `timeout` |
| 整批时限 | 30000 ms | 到点返回部分结果 + 统计 |
| 搜索深度 | 12 | 迭代加深上限 |
| 搜索状态数 | 200000 | 展开上限 |
| 证书步数 | 2000 | 沿用 kernel 上限 |

统计字段：`candidates`、`coveredNodes`、`durationMs`、`verified`、`refuted`、`undecided`、
`unprocessed`、`runVersion`、`generatorVersion`、`checkerSha256`。

**这些默认值是按实测调的，不是数学条件。** 依据（2026-10-04 实测，同一条目标
`∀mul0 e0 inv0. abelian_group(mul0)(e0)(inv0) ⇒ group_concept(mul0)(e0)(inv0)`）：

| 预算 | 结果 |
|---|---|
| 2000 ms / 10000 状态 / depth 8（旧默认） | `timeout`（2011 ms 烧完，才 2374 个状态） |
| 20000 ms / 10000 状态 / depth 8 | `timeout`（状态数 10001 打满） |
| 20000 ms / 40000 状态 / depth 12 | **`proved`**（18333 个状态，7.7 s） |

所以「够不够」取决于**状态数**而不是墙钟：只看时间的预算会把这类"三步量词链 + 定义展开"
的目标记成 `timeout`，而 `timeout` 是 `undecided`，不是"证不出来"。

**两条必须如实报告的工程事实**（写进 `stats`，不要粉饰）：

1. 同步路径**无法中断单个候选**（同步 JS 打不断自己）。整批时限只在**候选之间**检查，
   因此实际耗时可能超过 `totalMs`。`stats` 里要有 `timedOut`、`budget.interruptible: false`、
   `overBudget` 与一条 `warnings` 说明这件事。
2. `unprocessed`（候选上限截断）与 `timedOut`（时限截断）**分开计数**——
   "还有多少没看"和"看了多少没看完"不是同一件事。

## 4. 首版证明能力的诚实边界

**能做**：

- 定义展开（`definition` 规则）+ λ 应用化简（走 `abstraction` 公理实例）；
- 假设引入、蕴含引入/消去、合取引入/消去；
- 全称引入（本征变量）/消去、存在引入/消去；
- 等式自反与指定上下文中的等式替换；
- 引用**已重放通过的局部引理证书**（`theorem` 规则，要求其开放假设为空）。

**不做（首版明确标为范围之外）**：

- 一般高阶合一、参数化引理的自动提升（`lift` 参数须由登记处给出）；
- 析取与经典反证（内核无规则）；
- 跨载体遗忘映射、一般理论解释、自动对偶发现；
- 自然语言/LaTeX 自动翻译；
- 任意模型的自动搜索、"完整数学证明助手"。

**注意 `lift` 的坑**：`term_sub` 不进入 `lift` 内部，所以「先提升再实例化参数」
只能靠 `theorem` 规则引用一份**参数化已固定**的已证引理，或在生成时就把参数填好。
生成器必须在候选阶段就决定参数，搜索阶段不得指望"事后填参数"。

**`abstraction` 公理实例的构造要求**（`kernel.axiom` 的 `abstraction` 分支）：

```python
a = source(spec['term'], sig); need(a[0] == 'lam')
f = ∀(params(a)) ∀x. (lift(a) x = lift(open_body(a[2], x)))
```

- `spec['term']` 必须是**规范 λ 项**（`['lam', type, body]`），
  `a` 的**自由变量表 `parameters(a)` 按规范序列化字典序排序**，x 取一个避开
  `object_fv(a)` 与 `sig['constants']` 的新名（kernel 用 `fresh`：`z0, z1, …`）。
- 还原这条公式时 Node 侧必须复刻 `parameters()` 的排序（`sorted(..., key=stable)`）
  与 `fresh()` 的取名规则，否则 `same()` 判定不过 → `forged H_Sigma instance`。
  由 `tests/formal-language.test.mjs` 的「H_Sigma 实例构造对拍」核对。
- 这就是首版唯一允许的 β 通道：**应用一个 `lift` 符号于实参**，等价于把实参代进抽象体。

## 6. 入库与回滚（写死在流程里）

**发布顺序**（任一步失败 → 原版本继续生效）：

1. 固定待发布清单，核对草稿修订、本体版本、形式背景版本。
2. **重放**选定证据，重新生成关系目标并核对假设。
3. 在隔离区合成候选本体，跑形成检查 / 引用封闭 / 证据核对 / 关系方向 / M-E 边界检查。
4. 写入**不可变**内容包，回读核对哈希。
5. 在单写入锁下复核当前版本，**原子**切换 `active.json`。
6. 更新服务端本体快照，返回新版本与新增节点入口。

**回滚**：创建**新的一条** revision（`kind:'rollback'`），恢复选定历史内容状态；
不删除历史包、证据或学习者记录；同时处理其后依赖新增节点的关系与契约，
保证当前公共网络**没有悬空引用**。

**幂等**：重复提交同一发布请求（同 `draftRevision` + `ontologyVersion` + `reviewDigest` +
`idempotencyKey`）返回同一结果。

#### 8.5.1 `discoverRelations` 必须装配的 `ctx`（六个判定器全靠它）

判定器自己不读盘；它们从 `ctx` 取下面这些键。**少一个键，确认环节就会静默退化成
`unsupported` / `undecided`——看起来"跑了"，其实什么都没证。** 所以这是硬契约
（`tests/relation-discovery-e2e.mjs` 会核对 `stats.engineReady` 与逐条候选的 `confirm` 结果）：

| 键 | 形状 | 谁造 | 缺了会怎样 |
|---|---|---|---|
| `ctx.specs` | `FormalSpec[]`（已归一） | `data/formal/registry.mjs` | 判定器没有候选 |
| `ctx.registry` | 登记表模块本身 | 调用方 | 同上 |
| `ctx.sig` | kernel 签名 `{ bases, constants: {name: 类型节点}, definitions }` | 背景签名 + 登记表声明 | 目标解析与证书装配全失败 |
| `ctx.variables` | `{ name: 类型节点 }`：**全部 spec 声明的自由参数** | 登记表 | 目标里的 `xx`/`aa`/`mul0` 推断不出类型 |
| `ctx.theory` | kernel theory `{ id, version, bases, constants, definitions, axioms }` | `buildKernelTheory` | `assembleBundle` 没有理论 |
| `ctx.theoryAxioms` | `[{ id, formula }]`（kernel 形状，公式**闭**） | 同上 | `theory` 步骤没有 witness |
| `ctx.definitions` | `Map<name, formula>`：`Name ≜ lift(term)` | 背景定义 + spec 定义 | `definition` 步骤无法登记 |
| `ctx.clauses` | `[{ id, kind, formula }]`，`kind ∈ axiom/definition/hypothesis/lemma` | 背景公理 + 概念展开 + 定义 | 搜索没有可用推理起点 |
| `ctx.lemmas` | `[{ id, conclusion, proofId, proofs? }]`（**开放假设必须为空**） | `lemmas.mjs` 闭合既有证书 | 既有四份证书无法复用 |
| `ctx.models` | 有限对象（`REGISTERED_INSTANCES`） | `data/formal/instances.mjs` | 有限实例与反例判不了 |

两条由此推出的硬要求：

1. **背景的「概念展开」必须以闭公式进 `ctx.theoryAxioms`。** 否则「阿贝尔群 ⇒ 群」这类特化
   目标在纯简单类型论里推不出来（`abelian_group` 只是原子谓词，展开不写进理论就没有推理起点）。
   这些公式会进 `theory_sha256`，所以「这份证书假定了什么」是可核的、可版本化的。
2. **`search` 的 `program` 形状是 `{ hypotheses, clauses }`，而 `clauses.mjs` 的
   `clausifyFormula()` 返回的是 `{clauses:[{head,body,vars}]}`。** 两者之间必须有**一个**
   显式转换（建议 `clauses.mjs` 导出 `toProgram()`），不允许每个调用方各写一份——
   两份转换就是两个事实，迟早一边能搜到、一边搜不到。

#### 8.5.2 `closeCertificate`：把既有证书变成可复用的闭引理

既有四份证书的结论里有**自由变量**、且带**开放假设**（例：group 证书结论 `g = h`、
开放假设 `equal_left_translations`）。kernel 的 `theorem` 规则**拒绝**引用开放假设非空的引理，
所以必须先闭合：

```
结论 = ∀v1…vn. h1 ⇒ … ⇒ hm ⇒ 原结论      （vi = 结论的自由变量，hj = 开放假设）
构造 = 同一 proof 内逐个 imp_i 消掉 assume 叶子，再在最外层套 all_i
```

- **本征变量条件**：`vi` 不得出现在任一开放假设里；违反就如实报冲突，**不许改名蒙过去**。
- `all_i` 的嵌套顺序与变量顺序相反（最外层是 `v1`）。
- 闭合后的引理必须 `open_hypotheses = {}`，否则 `theorem` 规则仍然拒绝它。
