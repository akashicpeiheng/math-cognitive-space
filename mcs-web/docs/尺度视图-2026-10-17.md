# 尺度视图：分子 / 节点 / 单元 / 话题（2026-10-17）

**定位。** 本文记录 `/network` 新增的四层尺度视图：同一画布可同时显示分子、节点、单元、话题；四层对象都可直接拖动（带抬升/回位动效）；右键大尺度对象可分裂为已登记的小尺度成员；缩小时可选择把临近的同一父对象成员自动合拢到下一尺度。

实现日期 2026-10-17。尺度登记是**派生投影**（D），不是对本体 M 的最终重判：不修改 `data/cases/*.mjs`、不修改既有 `granularity`、不改 `ontology.contentHash`，也不写学习者档案 E。界面上的「分裂/合拢」只改变本页显示。

## 1. 依据

- `mcs-foundations/notes/数学对象六级尺度模型.md`：原子—分子—节点—单元—话题—子学科；原子/分子是相对固定语法的构造尺度，节点由中心对象、先修与目标确定，单元/话题/子学科按成员类型逐级聚合。
- `mcs-foundations/09-话题、领域、学科与元理论.md` 定义 9.1–9.6：成员严格低一级、允许交叉归属、无环；整体关系只能读作存在联系（R∃）或覆盖（R_cov），不得把整体联系说成整体先修。
- `mcs-foundations/publication/接口迁移表.md`：旧多层话题 → 单元；旧话题/领域/学科按内容重判。
- `mcs-foundations/04-节点生成与身份.md` 定义 4.12：学习节点的中心对象可以是分子；尺度与内容角色是两套坐标。

本视图只实现用户点名的四层。原子作为分子卡片内的文字明细（不在画布上单独成对象）；子学科不在本视图新增层。

## 2. 尺度登记怎么来

`data/scale.mjs` 逐条写映射，`core/scale.mjs` 构建并校验，`GET /api/v2/ontology/scale` 只读下发。**每个 `kind:'topic'` 聚合必须恰好登记一次**；漏一个或写错一个，`npm run check` 与接口都会报错。

| 现有来源 | 登记为 | 规则 |
|---|---|---|
| 11 个内聚聚合：`agg-limit`、`agg-manifold`、`agg-tensor`、`agg-group`、`agg-dg`、`agg-top-foundation`、`agg-top-compactness`、`agg-top-manifold`、`agg-top-counterexample`、`agg-top-method`、`agg-vault-analysis` | 单元 | 聚合整体即对象族/工具族；成员 = 全部 block 展平 |
| 4 条教材路径：`agg-liang-volume-1`、`agg-rudin-pma`、`agg-jiang-jdga`、`agg-axler-ladr` | 路径组 + 单元 | 每个 block = 一个单元（共 43 个）；聚合本身只作面板分组，不是画布对象 |
| 显式话题 | 话题 | `topic:manifold-calculus`（3 个单元）、`topic:point-set-topology`（5 个单元） |
| 显式分子 | 分子 | 拓扑流形的 \(P_n=H\wedge(C\wedge L_n)\)，以及 8 条 `top` 断言的形式式 |

当前快照：**54 个单元、2 个话题、9 个分子、4 个路径组**；305/405 个节点有单元归属，其余 100 个作为无单元的节点根显示。计数由接口 `counts` 动态给出，界面不抄死。

- 单元/话题 id：`unit:<aggregateId>` 或 `unit:<aggregateId>:<blockIndex>`；`topic:<slug>`；分子 id：`mol:<nodeId>`。
- 单元/话题全部标 `provisional: true`、`evidenceStatus: 'ILLUSTRATION'`，界面标「迁移登记」。教材块单元若标题由成员标题生成，标 `titleSource: 'derived'`，不冒充人工命名。
- 分子是显式登记；每条都写父节点、表达式、原子明细与来源（专稿实例或节点 `formal.formula`）。没有登记中心分子的节点不能分裂到分子层，菜单会如实说明。

## 3. 视图规则

### 3.1 可见性

- 话题/单元只有在被显式加入或由已展开父对象派生时才出现在画布上；`split` 是展开账本。
- 节点若其可见主父单元/话题尚未展开，则被隐藏；没有可见祖先时作为节点根显示。
- **主父对象按当前可见父对象选**，不是全库按 id 排序的第一个。跨归属节点（如「坐标卡」同时属于 `agg-dg` 与 `agg-top-manifold`）因此不会出现「展开单元 A 却只合拢一半成员」。
- 合拢只从可见集删除子对象，不删除 `added`/`split`；放大后原样恢复。

### 3.2 自动合拢

阈值与「临近」判据登记在 `web/src/scale-network.ts` 的 `SCALE_LOD`，并由 `data/design-values.mjs` 核对：

| 小尺度 → 父尺度 | 缩放阈值 | 条件 |
|---|---|---|
| 分子 → 节点 | ≤ 90% | 父节点可见；分子是节点明细，单个也收 |
| 节点 → 单元 | ≤ 55% | 该单元的全部节点都在视图中、主父都是它、当前缩放下屏幕包围盒 ≤320px |
| 单元 → 话题 | ≤ 30% | 该话题的全部单元都可见、主父都是它、屏幕包围盒 ≤320px |

- **不编造父对象**：自动合拢只合并登记过的父对象下的成员；没有父对象的节点/单元永不自动合并。
- **成员不全或分散不合并**：这正对应「临近」；界面保留成员并写「可见/全部」计数。
- **滞后带 0.06**：已合拢的要放大到阈值 + 0.06 才解开，避免阈值附近抖动。
- **手动展开优先一轮**：在阈值以下点「分裂」，新成员不会在同一帧被 LOD 收回去；用户一动缩放（滚轮/按钮/双指）就恢复按阈值合拢。
- 合拢/解开**不移动相机**；手动分裂后相机适配到「父对象 + 新成员」的可见包围盒。

### 3.3 拖动与动效

- **节点尺度**是四层里的基础对象：节点卡片/圆点沿用原来的拖动逻辑，拖动时卡片抬升、圆点放大，落手后写回节点位置；不需要先“加入节点尺度”。面板另提供「加入节点尺度」按钮，方便用户把已加入单元/话题的成员节点一口气放上画布。
- 分子卡片、单元 header/card、话题 header 都可以直接拖动。拖动按当前缩放的**世界坐标**更新左上角，成员线、聚合边和相机适配都跟着新位置算。
- 手动位置单独存 `mcs-network-scale-positions-v1`（与节点位置分开），并随命名视图/会话暂存保存；旧快照没有该字段时按自动布局恢复。
- 拖动本身不改变成员归属、不写本体、不写 E；只是显示层的手动摆放。
- 动效只在显示层：`.network-scale-object` 拖动时 inner 卡片 `scale(1.045)` + 阴影，节点卡片 `scale(1.035)`、圆点 `scale(1.2)`；卡片入场淡入；尊重 `prefers-reduced-motion`。

### 3.4 边

- 节点之间的边行为不变。被隐藏节点的边投影到最近可见祖先（合拢卡片），同一对显示对象合并成一条，带「N 条联系」计数。
- 聚合边必须标成**存在联系（R∃）**，不读成整体先修（09 定义 9.8）。
- 新增「尺度归属」虚线边（父 header/card → 可见子对象），可在尺度面板关闭；它不是语义前提。
- 合拢后节点仍在 `added` 里，推荐/起始节点的口径不变；图例明说「已合拢仍计入本视图」。

### 3.5 视觉

- 节点卡片/圆点、形状阈值与颜色**不变**。
- 尺度卡片是**屏幕恒定大小**（外层 `scale(1/zoom)`），25% 下仍可读；话题实线强调、单元虚线、分子点线。
- 有可见后代的父对象是 header（贴在后代包围盒上方）；没有可见后代的是 card，放在顶部码头或上一次锚点。
- 卡片只用现有主题令牌，不新增颜色；深色模式沿用现有变量。
- 拖动后的手动位置优先于成员包围盒/码头；拖动时抬升，落手平滑回位；节点与尺度卡片共用同一套“可拖动”视觉语言。

## 4. 入口与状态

- HUD「尺度」开关：关闭时页面与旧版完全一致；打开默认启用四层并打开「尺度对象」面板一次。
- 「尺度对象」面板：四层复选、自动合拢开关、尺度归属连线开关、**节点尺度入口**（标明画布节点可拖动，并提供「加入节点尺度」：把已加入单元/话题的成员节点放上画布；没有尺度对象时加入全部节点）、搜索、54 个单元按话题/教材路径分组、加入/移出/展开/合拢。
- 右键话题/单元：「分裂为小尺度对象（N 个）」/「合拢」/「查看成员与依据」/「从视图移出」。
- 右键节点：保留原有菜单项，追加「分裂为中心分子」；没有登记时禁用并写明。
- 触屏没有右键：面板每行与详情面板都有同一条展开/合拢按钮。
- URL 参数：`scales`（`all` 或逗号分隔）、`scaleNodes`（显式加入的尺度根）、`split`（已展开的对象，含节点）、`merge=0`（关闭自动合拢）。长参数与 `nodes` 一起进 fragment。
- 本次学习暂存与命名视图都保存 `scale` 状态与 `scale.positions`（手动拖过的卡片左上角）；旧快照没有这些字段时载入结果与旧版一致。
- 保存视图仍只写 E，且只在用户显式点「保存当前视图」时发生；展开/合拢本身不写 E、不产生学习事件。

## 5. 未覆盖与边界

- 尺度分类是**暂定迁移**：11 个聚合整体作单元、教材块作单元、2 个显式话题、9 个显式分子；没有按六级模型逐条重判。界面与接口都标 `provisional-migration`。
- 100 个节点尚未进入任何聚合块，保持无单元节点根；不为了「全部分组」编造单元。
- 原子与子学科不在本视图；原子只在分子详情内列出。
- 自动合拢只处理登记父子关系；空间上相邻但没有登记关系的对象不会合并。
- 尺度卡片位置冲突只做有界避让；手动拖动后不保证任意极端密度下绝对不重叠。
- 聚合边 v1 不做曲线避让，只画直线/轻微弧线。
- 未做真实学习者实验；阈值是设计取值，不是教学效果结论。
