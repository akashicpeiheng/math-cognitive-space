## 1. 界面文案改造（B2）

### 放哪里

- **通用壳层文案**（导航、按钮、通用动作、无障碍标签）→ `web/src/i18n/messages.ts`，**成对**写
  `{ zh: '…', en: '…' }`。成对写法的价值：漏一个键就编译不过。
- **页面自己的长文案**（首页六幕、介绍页、方法库、范例路径）→ 该页自己的模块，按
  `{ zh, en }` 成对导出；不要往 `messages.ts` 堆。
- **受控词表的显示名**（构造类型、角色、关系种类、事件种类…）→ `web/src/labels.ts` 的成对表。

### 组件里怎么用

```tsx
import { useI18n } from '../i18n';
import { useLabels } from '../labels';

const { t, locale, fmtDate, isPending, hrefFor } = useI18n();
const labels = useLabels();
```

- 文字：`t('nav.nodes')`（键未登记时返回键名本身，不会返回空白）
- 词表：`labels.constructLabel(node.construct)`、`labels.tables.constructs`（摊平后的表，给 `<option>` 用）
- 时间：`fmtDate(value)`（**不要**再写 `toLocaleString('zh-CN')`）
- 跳转：站内相对路径（`to="nodes"`）即可，`Link`/`NavLink` 会带上当前语种前缀；
  需要拼完整字符串时用 `hrefFor('/nodes')`
- 未译标注：`isPending(node.title)` 为真时给标题加 `className="i18n-pending"` 与
  `title={t('i18n.pendingTitle')}`（英文站上回落到中文原文的条目必须标出来）

### 非组件模块

`facets.ts`、`authoring.ts`、`network.ts` 这类纯函数模块**不要**引入 React。做法：
函数多收一个 `locale: Locale = 'zh'` 参数，或把成对表当参数传进来。调用方（组件）负责传当前语种。

### 不要动的东西

- 中文文案**逐字不变**：`npm test` 里几十条断言直接比对中文串，改一个字就会红。
- 不要给中文站加 `?locale=zh`：中文是默认语种，`api.ts` 已经保证中文请求与从前逐字相同。

## 2. 内容翻译（B3）

### 文件与形状

覆盖目录 `data/i18n/en/`，按**案例**拆文件：

```
en/limit.mjs     en/manifold.mjs   en/tensor.mjs   en/group.mjs
en/dg.mjs        en/liang.mjs      en/rudin.mjs
en/actions.mjs     聚合各案例的 actions
en/evidence.mjs    聚合各案例的 evidence
en/relations.mjs   聚合各案例的 relations
en/localizations.mjs  36 个局部化算子的名称/定义/边界
en/objects.mjs     站点级六节：patterns / claims / support / aggregates / templates / coverage
en/meta.mjs        段落级：signature / theory / environmentBoundary
en/cases.mjs       案例正文块（`<!-- node:id -->` → 英文 Markdown）
en/cases-dg.mjs    微分几何那 30 个正文块（生成物的英文覆盖，单独一份）
```

**注册表在 `data/i18n/index.mjs` 的 `REGISTRY`**：一个覆盖文件必须在那里登记才会被装配。
登记是**按文件逐条容错的**（某个文件还没建 = 那一块记为缺口，其余照常生效），
但**没登记 = 白写**（译了也不会有任何效果）。新开一节或新增案例文件时，先看注册表。

单个文件形状（照抄 `data/i18n/en/limit.mjs` 的结构）：

```js
export default {
  nodes: { 'limit:distance': { title: '…', summary: '…', formal: { … }, motivation: { … }, teaching: { … }, provenance: { note: '…' } } },
  representations: { 'rep-limit-distance-formula': { title: '…', medium: 'formula' } },
  actions: { 'a-limit:distance': { title: '…' } },
  evidence: { 'ev-limit-bridge-proof': { title: '…', scope: '…', obligations: ['…'] } },
  relations: { 'rel-…': { scope: '…' } },
};
```

### 导出待译字段

```bash
node scripts/i18n-extract.mjs --case manifold --out tmp/i18n/manifold.zh.json
node scripts/i18n-extract.mjs --case manifold --ids-only     # 只看体量
node scripts/i18n-inventory.mjs                              # 全库字段与汉字数
```

### 硬规则（`scripts/i18n-parity.mjs` 会逐条核对）

1. **键 = 中文源的 id**，一个字都不能改；覆盖里出现不存在的 id 直接报错。
2. **只写含中文的字段**。不要把 `discipline`、`roles`、`mode`、`typeEnv`、`symbols` 抄一遍
   ——受控词表值与结构不属于译文。
3. **数组按序对齐、长度必须相同**：`teaching.conditions[0]` 对应中文源的第 0 个条件。
   宁可少写一条（留中文）也不要截断数组。
4. **数学记号原样保留**：LaTeX（`\forall`、`\varepsilon`…）、`$…$` 定界符数量、
   量词符号（`∀∃εδ→⇔⇒⊢∈⊂≤≥≠`）、数字、证据标签（`DEF/PROOF/REF/FINITE/ILLUSTRATION/NOT-CLAIMED`）
   在译文里必须与中文源**数量一致**。公式从不翻译，只翻译公式周围的话。
5. **`provenance.sources` 与 `witness.ref` / `reference` 不翻译**：那是修订源的真实文件名
   （`mcs-foundations/cases/01-极限与连续.md`）。翻了就等于谎报来源。
6. 译文里**不许残留中文**（正文块、节点字段都是），唯一例外是上面第 5 条。
7. 正文块：`data/i18n/en/cases.mjs` 按 `<!-- node:id -->` 块给英文 Markdown，
   标题层级（`#` 的数量与顺序）必须与中文块一致。

### 语体

- 面向学习者，结论先行；先说「为什么需要它」，再说「它为什么长成这样」。
- 定理的每个条件要保留「删掉会怎样」的反例与后果（中文源怎么写，英文就怎么还给读者）。
- 不夸大：`REF` 就是引用，`not_run` 就是没跑过，`未声称` 译成 `not claimed`，
  不要把「教材里有论证」译成「已验证」。

### 踩过的坑（都是实测出来的，别重犯）

1. **反引号里的中文是标识符，不是漏译**。源文件路径（`` `G:/…/微分形式的外积.md` ``）与
   中文文献书名（`` `梅加强. 流形与几何初步` ``）**逐字照抄**，放在反引号里；散文里的中文才算漏译。
   两个检查工具（`i18n-parity.mjs`、`i18n-block-check.mjs`）都按这条规则豁免。
   把中文书名译成英文 = 替文献改名，读者查不到那本书。
2. **公式逐字照抄**，唯一例外是 `\text{…}` 里的中文说明（那里允许译成英文）。
   行内公式**允许换序**（中英语序不同），但个数与内容必须逐字相同；行间公式同理。
3. **JS 模板字符串里写 LaTeX 要写两层反斜杠**：`` `$\\mathbb R$` `` 才对。
   只写一层会被 JS 转义规则吃掉，输出成 `$mathbb` —— 公式悄悄坏掉，而人眼很容易看漏。
4. **术语表里以数字开头的键必须加引号**：`'4维速度': '4-velocity',`。
   不写引号会让 `glossary.mjs` 直接语法错误，整个 `overlayFor('en')` 抛错、**全站英文消失**。
   追加术语后跑一次冒烟：`node -e "await import('./data/i18n/glossary.mjs')"`。
5. **`formalStatement.notation[].symbol` 含中文时要译**（`f⁻¹ 连续` → `f⁻¹ continuous`）：
   它渲染在节点页的 `<code>` 里、不是 KaTeX，留着中文会在英文页露出来。只动散文，不动符号本身。
6. **不要为覆盖率牺牲准确**：宁可留中文（覆盖率如实记为缺口），也不要写占位直译、
   更不要用英文重述一个你不确定的数学断言。
7. **用字符串替换改 Markdown 时 `$$` 会被吃掉**。`String.prototype.replace(pat, str)`
   在替换值是**字符串**时把 `$$` 当转义序列，还原成一个 `$`——`$$…$$` 会静默降级成
   `$…$`（行间公式 8 段 → 7 段；检查能报差异，但不会告诉你原因）。做法：用
   **函数式替换** `text.replace(from, () => to)`（replacer 的返回值不做 `$` 展开），
   并在替换前断言 `text.split(from).length - 1 === 1`。
8. **译名里的版本号与卷次会被「数字同构」抓到**。parity 逐字段比对数字多重集：
   中文源 `第 2 版` 含数字 `2`，译文写 `second edition` 就丢了数字（报 `numbers 不一致`）；
   反向多写数字同样报错。做法：版本、卷次、章节号一律用**保留数字**的写法
   （`Vol. 2`、`2nd ed.`、`Chapter 2`、`§2.2`）；必须用文字时，把该标识整体放进反引号
   随中文原名一起保留。
9. **`relations` / `templates` / `coverage` 三节的「行键」不是一回事**（三条都踩过）：
   关系集合在运行时的键叫 `relationDescriptions`（覆盖里叫 `relations`）；模板的行键是
   `role`；覆盖表的行键是 `chapter`。**装配层、覆盖率、parity 三处必须用同一个
   `keyOf()` 取键**（`data/i18n/overlay.mjs`）——各写各的那一次，结果是「译文写了但永远
   不生效，而覆盖率报满」。
10. **公式之外，源文的 Markdown 排版**也是**结构**，不许「顺手整理得更规整」**：
    - **行尾两空格的硬换行**（Markdown 的 `  \n` → `<br>`）：中文源用它把三行排成一组，
      英文接成普通换行就会被算成一段（实测 `dg:homeomorphism` 因此报「中 9 段 / 英 6 段」）；
    - **标题前是否留空行**：中文源里标题可能**紧贴上一段**（同属一个空行块），补一个空行
      就会多出一个分块；
    - **多余的 `---` 分隔线**：中文源没有就不要加（实测 `dg:smooth-atlas` 115→116）。

    判据的设计意图正是如此：中文源的教学排版本身就是信息（一段一论点、条件与反例成对）。
    「把它整理成更规范的 Markdown」在别的项目里是好事，**在这里是改动结构**。
11. **公式里的括号也是内容**：「顺手补全」是这批块里出现最多的一类错——
    `$n-1$` 被写成 `$(n-1)$`、`$D$` 被写成 `$D\subset M$`、`$n-r$` 被写成 `$(n-r)$`。
    源文没有的括号、范围、假设**一个都不能加**；同理「$f$ 的导数」里的 `$f$` 不能吞成普通词。
12. **公式内部的一切都是结构**：一个公式**不能拆成两个**（`$x, y$` ≠ `$x$` + `$y$`；
    `$T_3, T_4$` ≠ `$T_3$` + `$T_4$`）；`\text{}` 的**组数**不能增减（内容可译、组数不可动）；
    **量词不能搬进散文**（`$\forall y \in A$` 不能写成 "for every $y \in A$"）——
    点集拓扑与几何笔记里这一类是**高频坑**。
13. **按下标/位置对齐的比较，对「增删」零容忍**（工具实现者尤其要看）：
    - 剔除一个元素后仍按下标配对 → 后面**整体错位**，1 处差异被报成几十项
      （实测：`check-one.mjs` 报过 1 处 → 60 项；剔除豁免项之后同理）；
    - 「抠掉一段再比对位置」的遮蔽**必须等长**，否则后面所有位置全错
      （`\text{闭 $p$-形式}` 里的 `$` 会打乱公式配对，遮蔽时长度一变就崩）。
    正确做法：**比多重集差集**，只报真正多/少的那几个。这与「按标题切节、不按序号硬比」
    是同一条经验：**一旦假设了对应关系，一处增删就会放大成成片假差异。**
14. **判断「某个条件是否成立」必须看原文，不能看归一化后的值**——这一类会**静默失效**：
    豁免条件永远为假、工具不报错、只是从不生效，看起来「检查通过了」其实是没检查。
    实例：用 `normMath` 之后的值判「这个公式含不含中文」，而 `normMath` 恰好把裸写的中文
    换成了占位符 → 判断恒为假（这一处栽了三次，最后靠**给工具插桩打印**才看清）。
    **通用前置断言**：凡做豁免，都断言**两侧剔除的条数相等**——它把「豁免静默失效」
    变成「当场报错」。
15. **一个约束只在一个地方检查**。同一约束写两处不是更保险，是**更容易误伤**：
    一处放宽了豁免、另一处没跟上，就会长期挂着一个假红。
    实例：LaTeX 命令集在两支脚本里各数一遍，`i18n-parity` 那处反复误报同一个块；
    删掉重复、改为「一个地方检查、另一处只留一条哨兵（检查脚本是否存在）」之后即绿。

- 术语一律查 `data/i18n/glossary.mjs`；新术语先加进术语表再用。

## 5. 人工复核清单与已知源缺陷

**工具查不到的、必须人看的**（这一节比「判据全绿」更重要——写出来是为了不让读者把
「判据全绿」读成「译文已核对」）：

- **句内加粗的保真**：结构判据只问「这一段里有没有加粗」，不查个数与位置（查位置会被
  中英语序差异误报）。所以 `公理里**没有**分离性` 这类**句内**加粗若被漏掉，工具不会响。
- **数学正确性**：两道门都不检查。把「不收敛」译成「收敛」、把条件的方向译反，工具看不出来。
- **措辞是否被抬高**：`REF` / `not_run` 附近的英文有没有被写成 verified / certified——
  工具只比标签的**计数**，不比它的语气。
- **术语是否漂移**：同一个中文概念在不同块里的英文写法是否一致（例如 `过渡映射`、
  `切矢量 vs 切向量`）。`glossary.mjs` 是基准，但没有任何判据强制逐块对齐。

**中文源自身的缺陷（不是译者的账，也不在本轮修）**

修它们会改变 `contentHash`（= 本体版本号），所以属于**单独的站点内容变更**，
不能搭在双语改造里顺手做掉。检查工具把这类问题**单独列出来**，并从相应判据里豁免对应段落：

| 类型 | 实例 | 后果与处置 |
|---|---|---|
| 加粗标记不平衡（奇数个 `**`） | `liang:minkowski-spacetime` 的 `**动机. 第一章…`；`dg:tensor`、`dg:tensor-product-dg`（2 处）、`dg:differential-form` 各 1 处 | 中文页面上那一行不成强调，且把后文一起吞成粗体。该类段落**豁免结构比对** |
| 公式里 `\text{}` 之外混中文 | `dg:topological-space` 的 `$f^{-1}(开集)$`（全库仅 1 处） | 该公式**从内容比对中剔除**（两侧同时）；译文改写为 `$f^{-1}(\text{open set})$` 是产品上正确的做法，不该被门冤枉 |
| 引导词写法不统一（成对但格式错） | `liang` 各块里 `**动机. **`（收尾 `**` 前多空格）与 `**动机。**` **并存**；另有大量引导词以半角句点收尾 | 只影响排版观感，不影响译文核对。工具按「几处、在哪些块」汇总，是否统一由人决定 |

判据的三轮收紧过程记在 `scripts/i18n-block-check.mjs` 的注释里（任意加粗配对计数 →
段首计数 → 只看段落内有无）：前两版各报出 5–8 条**假阳性**，最终版只抓真问题，
代价是「句内加粗」不再受保护——这条写进上面的「必须人看」清单，而不是假装它还在覆盖。

## 6. 定位型工具：判据只给聚合信号，定位要靠逐项差分

判据（`i18n-parity` / `i18n-block-check`）只回答「有没有不一致、大概在哪一节」。
要把一处差异**定位到具体那一段**，靠下面这套（多位译者各自写过，做法一致，值得固化）：

| 手段 | 干什么 | 为什么不能省 |
|---|---|---|
| **多重集差分** | 按公式/链接的**内容**聚合计数再比，不按序号对齐 | 按序号打印会把 1 处真差异放大成一串（实测：真差异 3 处、输出 18 行）。**先看有没有、再看在哪** |
| **逐行出现数** | 给定一个公式原文，打印两侧「行号 × 个数」+ 该行文本 | 公式被吞、被改写、被合并一眼可见 |
| **链接差分** | 同上但针对 `/nodes/<id>` | 「指错节点」与「漏一个」在**计数上可能完全一样**，只有逐项差分抓得到 |
| **结构预演** | 在装配**之前**把结构判据本地跑一遍（分块数、逐段引导词、硬换行、紧贴标题） | 否则「未装配的块 = 未验证的块」，等装配再发现要重跑一轮 |
| **跨源复用** | 把单块自检脚本参数化到别的案例源文件 | `limit` 的 16 块就是用它自检的 |

三条经验（都是实测出来的）：

- **(a)** 计数不一致时**按标题切节**定位，不要按序号硬比（插入一段会让后续序号全漂移）；
- **(b)** 链接「指错节点」与「漏一个」在聚合计数上可能一样——**必须逐项差分**；
- **(c)** 公式被顺手改写（`$n$` ↔ `$\mathbb{R}^n$`、`$n-1$` ↔ `$(n-1)$`）对「命令集」检查
  **完全隐形**——这正是多重集差分存在的理由。
